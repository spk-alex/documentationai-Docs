# Matter Cluster 1365 — Push AV Stream Transport Cluster

<Callout type="info">
Matter Cluster <code>1365</code>, also written as <code>0x0555</code>, is the <strong>Push AV Stream Transport Cluster</strong>.
This cluster implements the upload of Audio and Video streams from the Camera AV Stream Management Cluster using suitable push-based transports. Push AV Stream Transport is the transmission of a stream of media to a server, initiated by the activation of an associated trigger. A push transport can be triggered from a camera operating in an always-on mode for supporting 24/7 style recording, triggered by events based on motion zones defined in the Zone Management Cluster, or manually triggered using commands or bindings.
</Callout>

## Bridge Command Payload Format

The bridge accepts Matter commands in this structure:

```json
{
  "message_id": "1",
  "command": "device_command",
  "args": {
    "endpoint_id": 1,
    "cluster_id": 1365,
    "command_name": "AllocatePushTransport",
    "payload": {},
    "timed_request_timeout_ms": 1000
  }
}
```

For Cluster 1365, always use `"cluster_id": 1365`. Payload keys are the command field names in lowerCamelCase. Octet-string fields are base64-encoded. `timed_request_timeout_ms` is required for timed commands and ignored otherwise.

## Event `0` — `PushTransportBegin`

This event indicates a push transport transmission has begun. With Motion and Continuous based triggers, this event is generated when each new recording starts uploading. With Command based triggers, this event is generated when uploading starts via the ManuallyTriggerTransport command.

| ID | Field | Type | Conformance | Meaning |
|---:|---|---|---|---|
| 0 | `ConnectionID` | PushTransportConnectionID | `M` | — |
| 1 | `TriggerType` | TransportTriggerTypeEnum | `M` | This field represents the type of trigger which caused this event to be generated. |
| 2 | `ActivationReason` | TriggerActivationReasonEnum | `TriggerType = Command` | This field only be present when the TriggerType is Command and provides the reason for the event. |
| 3 | `ContainerType` | ContainerFormatEnum | `ClusterRevision >= 2` | Indicates the container type chosen for this transport. |
| 4 | `CMAFSessionNumber` | uint64 | `ContainerType = CMAF` | — |

## Event `1` — `PushTransportEnd`

This event indicates a push transport upload of the indicated recording has completed. With Motion, Continuous, and Command based triggers, this event is generated when each new recording finishes uploading. The data on this event contains the following information.

| ID | Field | Type | Conformance | Meaning |
|---:|---|---|---|---|
| 0 | `ConnectionID` | PushTransportConnectionID | `M` | — |
| 1 | `ContainerType` | ContainerFormatEnum | `ClusterRevision >= 2` | Indicates the container type chosen for this transport. |
| 2 | `CMAFSessionNumber` | uint64 | `ContainerType = CMAF` | — |
