# Matter Cluster 1105 — Wi-Fi Network Management Cluster

<Callout type="info">
Matter Cluster <code>1105</code>, also written as <code>0x0451</code>, is the <strong>Wi-Fi Network Management Cluster</strong>.
This cluster provides an interface for getting information about the Wi-Fi network that a Network Infrastructure Manager device type provides. Privileged nodes within the same fabric as a Network Infrastructure Manager can use these interfaces to request information related to the Wi-Fi Network such as SSID and Passphrase.
</Callout>

## Attribute `1` / `0x0001` — `PassphraseSurrogate`

Path example:

```text
1/1105/1
```

This attribute contains an arbitrary numeric value; this value must increase whenever the passphrase or PSK associated with the primary Wi-Fi network provided by this device changes. A value of null indicates that no primary Wi-Fi network is available. Clients can subscribe to this attribute or compare its value to a locally cached copy to detect if a cached passphrase value has become stale. It is recommended that servers implement this attribute as either a timestamp or a counter.

| Property | Value |
|---|---|
| Type | uint64 |
| Conformance | `M` |
| Access | R (read: manage) |
| Qualities | nullable, persisted |

Example:

```json
{
  "1/1105/1": 1
}
```

## Bridge Command Payload Format

The bridge accepts Matter commands in this structure:

```json
{
  "message_id": "1",
  "command": "device_command",
  "args": {
    "endpoint_id": 1,
    "cluster_id": 1105,
    "command_name": "NetworkPassphraseRequest",
    "payload": {},
    "timed_request_timeout_ms": 1000
  }
}
```

For Cluster 1105, always use `"cluster_id": 1105`. Payload keys are the command field names in lowerCamelCase. Octet-string fields are base64-encoded. `timed_request_timeout_ms` is required for timed commands and ignored otherwise.

# Command: `NetworkPassphraseRequest`

## Purpose

This command is used to request the current WPA-Personal passphrase or PSK associated with the Wi-Fi network provided by this device. If the command is not executed via a CASE session, the command is rejected with a status of UNSUPPORTED_ACCESS. If no primary Wi-Fi network is available (the SSID attribute is null), the command is rejected with a status of INVALID_IN_STATE. Otherwise a NetworkPassphraseResponse is generated.

## Command Identity

| Field | Value |
|---|---|
| Command ID | `0` |
| Command hex | `0x00` |
| Command name | `NetworkPassphraseRequest` |
| Direction | client → server |
| Conformance | `M` |
| Response | NetworkPassphraseResponse |
| Access | (invoke: manage) |

## Payload Fields

This command has no payload fields.

## Bridge Command Example

```json
{
  "message_id": "1",

    "endpoint_id": 1,

    "payload": {}
  }
```
