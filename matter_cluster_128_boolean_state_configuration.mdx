# Matter Cluster 128 — Boolean State Configuration Cluster

<Callout type="info">
Matter Cluster <code>128</code>, also written as <code>0x0080</code>, is the <strong>Boolean State Configuration Cluster</strong>.
This cluster is used to configure a boolean sensor, including optional state change alarm features and configuration of the sensitivity level associated with the sensor.
</Callout>

## Cluster 128 Features

The `FeatureMap` attribute (`1/128/65532`) is a bitmap. Each bit set means the device implements that feature and the attributes and commands that depend on it.

| Bit | Code | Feature | Conformance | Meaning |
|---:|---|---|---|---|
| 0 | `VIS` | Visual | `O` | Supports visual alarms |
| 1 | `AUD` | Audible | `O` | Supports audible alarms |
| 2 | `SPRS` | AlarmSuppress | `[VIS \| AUD]` | Supports ability to suppress or acknowledge alarms |
| 3 | `SENSLVL` | SensitivityLevel | `O` | Supports ability to set sensor sensitivity |
| 4 | `FAULTEV` | FaultEvents | `[ClusterRevision >= 2]` | Supports reporting fault events |

Example: `FeatureMap` = `0` means no optional feature is enabled; `31` means every feature listed above is enabled.

## Bridge Command Payload Format

The bridge accepts Matter commands in this structure:

```json
{
  "message_id": "1",
  "command": "device_command",
  "args": {
    "endpoint_id": 1,
    "cluster_id": 128,
    "command_name": "SuppressAlarm",
    "payload": {},
    "timed_request_timeout_ms": 1000
  }
}
```

For Cluster 128, always use `"cluster_id": 128`. Payload keys are the command field names in lowerCamelCase. Octet-string fields are base64-encoded. `timed_request_timeout_ms` is required for timed commands and ignored otherwise.

# Cluster 128 Events

| ID | Hex | Event | Priority | Conformance | Description |
|---:|---|---|---|---|---|
| 0 | `0x00` | `AlarmsStateChanged` | info | `VIS \| AUD` | This event is generated after any bits in the AlarmsActive and/or AlarmsSuppressed attributes change. |
| 1 | `0x01` | `SensorFault` | info | `FAULTEV, O` | This event is generated when the device registers or clears a fault. |

## Event `0` — `AlarmsStateChanged`

This event is generated after any bits in the AlarmsActive and/or AlarmsSuppressed attributes change. This may occur in situations such as when internal processing by the server determines that an alarm mode becomes active or inactive, or when the SuppressAlarm or EnableDisableAlarm commands are processed in a way that some alarm modes becomes suppressed, active or inactive. If several alarm modes change state at the same time, a single event combining multiple changes may be emitted instead of multiple events each representing a single change.

| ID | Field | Type | Conformance | Meaning |
|---:|---|---|---|---|
| 0 | `AlarmsActive` | AlarmModeBitmap | `M` | Indicates the state of active alarm modes, as indicated by the AlarmsActive attribute, at the time the event was generated. |
| 1 | `AlarmsSuppressed` | AlarmModeBitmap | `SPRS` | Indicates the state of suppressed alarm modes, as indicated by the AlarmsSuppressed attribute, at the time the event was generated. |

## Event `1` — `SensorFault`

This event is generated when the device registers or clears a fault.

| ID | Field | Type | Conformance | Meaning |
|---:|---|---|---|---|
| 0 | `SensorFault` | SensorFaultBitmap | `M` | Indicates the value of the SensorFault attribute, at the time this event is generated. |
