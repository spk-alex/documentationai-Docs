# Matter Cluster 96 — Operational State Cluster

<Callout type="info">
Matter Cluster <code>96</code>, also written as <code>0x0060</code>, is the <strong>Operational State Cluster</strong>.
This cluster supports remotely monitoring and, where supported, changing the operational state of any device where a state machine is a part of the operation. This cluster defines common states, scoped to this cluster (e.g. Stopped, Running, Paused, Error).
</Callout>

# Attribute Details

## Attribute `0` / `0x0000` — `PhaseList`

Path example:

```text
1/96/0
```

Indicates a list of names of different phases that the device can go through for the selected function or mode. The list may not be in sequence order. For example in a washing machine this could include items such as "pre-soak", "rinse", and "spin". These phases are manufacturer specific and may change when a different function or mode is selected.

| Property | Value |
|---|---|
| Type | list of string |
| Conformance | `M` |
| Access | R (read: view) |
| Qualities | nullable |
| Constraint | max 32 entries |
| Default | `MS` |

Example:

```json
{
  "1/96/0": []
}
```

## Attribute `2` / `0x0002` — `CountdownTime`

Path example:

```text
1/96/2
```

Indicates the estimated time left before the operation is completed, in seconds. A value of 0 (zero) means that the operation has completed. A value of null represents that there is no time currently defined until operation completion. This may happen, for example, because no operation is in progress or because the completion time is unknown.

| Qualities | nullable, quiet reporting |
| Constraint | max 259200 |

Path example:

```text

Details of the phase of a device when, for example, in a state of Running are provided by the CurrentPhase attribute. All devices must, at a minimum, expose the set of states matching the commands that are also supported by the cluster instance, in addition to Error.

## Bridge Command Payload Format

The bridge accepts Matter commands in this structure:

```json
{
  "message_id": "1",
  "command": "device_command",
  "args": {
    "endpoint_id": 1,
    "cluster_id": 96,
    "command_name": "Pause",
    "payload": {},
    "timed_request_timeout_ms": 1000
  }
}
```

For Cluster 96, always use `"cluster_id": 96`. Payload keys are the command field names in lowerCamelCase. Octet-string fields are base64-encoded. `timed_request_timeout_ms` is required for timed commands and ignored otherwise.

# Command: `Pause`

## Purpose

This command is supported if the device supports remotely pausing the operation. If this command is supported, the Resume command must also be supported. On receipt of this command, the device must pause its operation if it is possible based on the current function of the server. For example, if it is at a point where it is safe to do so and/or permitted, but can be restarted from the point at which pause occurred.

# Command: `Stop`

## Purpose

This command is supported if the device supports remotely stopping the operation. On receipt of this command, the device must stop its operation if it is at a position where it is safe to do so and/or permitted. Restart of the device following the receipt of the Stop command must require attended operation unless remote start is allowed by the device type and any jurisdiction governing remote operation of the device. If this command is received when already in the Stopped state the device must respond with an OperationalCommandResponse command with an ErrorStateID of NoError but take no further action.

# Command: `Start`

## Purpose

This command is supported if the device supports remotely starting the operation. If this command is supported, the 'Stop command must also be supported. On receipt of this command, the device must start its operation if it is safe to do so and the device is in an operational state from which it can be started. There may be either regulatory or manufacturer-imposed safety and security requirements that first necessitate some specific action at the device before a Start command can be honored.

# Command: `Resume`

## Purpose

This command is supported if the device supports remotely resuming the operation. If this command is supported, the Pause command must also be supported. On receipt of this command, the device must resume its operation from the point it was at when it received the Pause command, or from the point when it was paused by means outside of this cluster (for example by manual button press). If this command is received when already in the Running state the device must respond with an OperationalCommandResponse command with an ErrorStateID of NoError but take no further action.

# Command: `OperationalCommandResponse`

## Purpose

This command is supported by an implementation if any of the other commands defined by this cluster are supported (i.e. listed in the AcceptedCommandList global attribute). This command must also be supported by an implementation of a derived cluster as a response to any commands that may be additionally defined therein. # Cluster 96 Events

| ID | Hex | Event | Priority | Conformance | Description |
|---:|---|---|---|---|---|
| 0 | `0x00` | `OperationalError` | critical | `M` | This event is generated when a reportable error condition is detected. |
| 1 | `0x01` | `OperationCompletion` | info | `O` | This event should be generated when the overall operation ends, successfully or otherwise. |

## Event `0` — `OperationalError`

This event is generated when a reportable error condition is detected. A device that generates this event must also set the OperationalState attribute to Error, indicating an error condition. This event contains the following fields:

| ID | Field | Type | Conformance | Meaning |
|---:|---|---|---|---|
| 0 | `ErrorState` | ErrorStateStruct | `M` | — |

## Event `1` — `OperationCompletion`

This event should be generated when the overall operation ends, successfully or otherwise. For example, the completion of a cleaning operation in a Robot Vacuum Cleaner, or the completion of a wash cycle in a Washing Machine. It is highly recommended that appliances device types employing the Operational State cluster support this event, even if it is optional.

| ID | Field | Type | Conformance | Meaning |
|---:|---|---|---|---|
| 0 | `CompletionErrorCode` | enum8 | `M` | This field provides an indication of the state at the end of the operation. This field has a value from the ErrorStateEnum set. |
| 1 | `TotalOperationalTime` | elapsed-s (nullable) | `O` | The total operational time, in seconds, from when the operation was started via an initial Start command or autonomous/manual starting action, until the operation completed. This includes any time spent while paused. |
| 2 | `PausedTime` | elapsed-s (nullable) | `O` | The total time spent in the paused state, in seconds. There may be cases whereby the total paused time exceeds the maximum value that can be conveyed by this attribute, in such instances, this attribute is populated with null. |
