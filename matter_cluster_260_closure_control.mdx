# Matter Cluster 260 — Closure Control Cluster

<Callout type="info">
Matter Cluster <code>260</code>, also written as <code>0x0104</code>, is the <strong>Closure Control Cluster</strong>.
This cluster provides an interface for controlling a Closure.
</Callout>

## Cluster 260 Features

The `FeatureMap` attribute (`1/260/65532`) is a bitmap. Each bit set means the device implements that feature and the attributes and commands that depend on it.

| Bit | Code | Feature | Conformance | Meaning |
|---:|---|---|---|---|
| 0 | `PS` | Positioning | `O` | Supports Positioning with at least Fully Opened (0%) and Fully Closed (100%) discrete positions |
| 1 | `LT` | MotionLatching | `O` | Supports a latch (securing a position, or a state) |
| 2 | `IS` | Instantaneous | `O` | Supports the Instantaneous feature |
| 3 | `SP` | Speed | `[PS & !IS]` | Supports Speed motion throttling |
| 4 | `VT` | Ventilation | `[PS]` | Supports Ventilation discrete state |
| 5 | `PD` | Pedestrian | `[PS]` | Supports Pedestrian discrete state |
| 6 | `CL` | Calibration | `[PS]` | Supports the Calibration feature |
| 7 | `PT` | Protection | `O` | Supports the Protection feature |
| 8 | `MO` | ManuallyOperable | `O` | Supports the manual operation feature |

Example: `FeatureMap` = `0` means no optional feature is enabled; `511` means every feature listed above is enabled.

Path example:

```json
  "args": {
    "endpoint_id": 1,
    "cluster_id": 260,
    "command_name": "Stop",
    "payload": {},
    "timed_request_timeout_ms": 1000
  }
}
```

For Cluster 260, always use `"cluster_id": 260`. Payload keys are the command field names in lowerCamelCase. Octet-string fields are base64-encoded. `timed_request_timeout_ms` is required for timed commands and ignored otherwise.

# Command: `Stop`

## Purpose

On receipt of this command, the closure must stop its movement as fast as the closure is able too. If the server's MainState attribute has one of the following values: - Moving - WaitingForMotion - Calibrating then any motions is stopped and the MainState attribute is set to Stopped. A status code of SUCCESS must always be returned, regardless of the value of the MainState attribute when this command is received.

## Command Identity

| Field | Value |

| Command name | `Stop` |
| Direction | client → server |
| Conformance | `!IS` |

# Command: `MoveTo`

## Purpose

On receipt of this command, the closure must operate to update its position, latch state and/or motion speed. The rationale behind defining the conformance as being purely optional in the table above is to ensure that commands containing one or more fields related to unsupported features are still accepted, rather than being rejected outright. For example, if a simple client, which is not able to determine the capabilities of the server, invokes a command that includes both position and speed, a server that does not support the speed feature would simply ignore the speed field while still adjusting its position as requested.

## Command Identity

| Field | Value |
|---|---|
| Command ID | `1` |
| Command hex | `0x01` |
| Command name | `MoveTo` |
| Direction | client → server |
| Conformance | `M` |
| Response | status |
| Access | (invoke: operate, timed) |

## Payload Fields

| ID | Field | Payload key | Type | Conformance | Constraint | Meaning |
|---:|---|---|---|---|---|---|
| 0 | `Position` | `position` | TargetPositionEnum | `O` | — | Indicates the position where the closure is moving to, as defined in the TargetPositionEnum. |
| 1 | `Latch` | `latch` | bool | `O` | — | Indicates the desired latching state of the closure, as defined in the OverallCurrentStateStruct Latch Field. |
| 2 | `Speed` | `speed` | ThreeLevelAutoEnum | `O` | — | Indicates a desired overall speed of motion, as defined in the ThreeLevelAutoEnum. |

`Position` values (`TargetPositionEnum`): `0` = MoveToFullyClosed, `1` = MoveToFullyOpen, `2` = MoveToPedestrianPosition, `3` = MoveToVentilationPosition, `4` = MoveToSignaturePosition

## Bridge Command Example

```json
{
  "message_id": "1",
  "command": "device_command",
  "args": {
    "endpoint_id": 1,
    "cluster_id": 260,
    "command_name": "MoveTo",
    "payload": {
      "position": 0,
      "latch": true
    },
    "timed_request_timeout_ms": 1000
  }
}
```

This is a **timed command**: the bridge must send it inside a timed interaction, so `timed_request_timeout_ms` is required.

# Cluster 260 Events

| ID | Hex | Event | Priority | Conformance | Description |
|---:|---|---|---|---|---|
| 0 | `0x00` | `OperationalError` | critical | `M` | This event is generated when a reportable error condition is detected. |
| 1 | `0x01` | `MovementCompleted` | info | `!IS` | This event, if supported, is generated when the overall operation ends, either successfully or otherwise. |
| 2 | `0x02` | `EngageStateChanged` | info | `MO` | This event, if supported, is generated when the MainStateEnum attribute changes state to and from disengaged, indicating if the actuator is Engaged or Disengaged. |
| 3 | `0x03` | `SecureStateChanged` | info | `M` | This event, if supported, is generated when the SecureState field in the OverallCurrentState attribute changes. |

## Event `0` — `OperationalError`

This event is generated when a reportable error condition is detected. A closure that generates this event must also set the MainState attribute to Error, indicating an error condition. This event contains the following fields:

| ID | Field | Type | Conformance | Meaning |
|---:|---|---|---|---|
| 0 | `ErrorState` | list of ClosureErrorEnum | `M` | — |

## Event `1` — `MovementCompleted`

This event, if supported, is generated when the overall operation ends, either successfully or otherwise. For example, the event is sent upon the completion of a movement operation in a blind.

This event has no fields.

## Event `2` — `EngageStateChanged`

This event, if supported, is generated when the MainStateEnum attribute changes state to and from disengaged, indicating if the actuator is Engaged or Disengaged. This event contains the following fields: - True, when the actuator is in a Engaged state, actuator movements possible. - False, when the actuator is in a Disengaged state, preventing any actuator movements.

| ID | Field | Type | Conformance | Meaning |
|---:|---|---|---|---|
| 0 | `EngageValue` | bool | `M` | — |

## Event `3` — `SecureStateChanged`

This event, if supported, is generated when the SecureState field in the OverallCurrentState attribute changes. It is used to indicate whether a closure is securing a space against possible unauthorized entry. This event contains the following fields: - True, when the closure is in a secure state, e.g. unauthorized/undetectable access is not possible. - False, when the closure is in an insecure state, e.g. unauthorized/undetectable access is possible.

| ID | Field | Type | Conformance | Meaning |
|---:|---|---|---|---|
| 0 | `SecureValue` | bool | `M` | — |
