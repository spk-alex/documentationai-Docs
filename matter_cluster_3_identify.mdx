# Matter Cluster 3 — Identify Cluster

<Callout type="info">
Matter Cluster <code>3</code>, also written as <code>0x0003</code>, is the <strong>Identify Cluster</strong>.
This cluster supports an endpoint identification state (e.g., flashing a light), that indicates to an observer (e.g., an installer) which of several nodes and/or endpoints it is. It also supports a multicast request that any endpoint that is identifying itself to respond to the initiator. The state of this cluster may be shared on more than one endpoint on a node.
</Callout>

# Attribute Details

## Attribute `0` / `0x0000` — `IdentifyTime`

Path example:

```text
1/3/0
```

Indicates the remaining length of time, in seconds, that the endpoint will continue to identify itself. If this attribute is set to a value other than 0 then the device must enter its identification state, in order to indicate to an observer which of several nodes and/or endpoints it is. It is recommended that this state consists of flashing a light with a period of 0.5 seconds. The IdentifyTime attribute is decremented every second while in this state.

| Property | Value |
|---|---|
| Type | uint16 |
| Conformance | `M` |
| Access | R/W (read: view, write: operate) |
| Qualities | quiet reporting |

Example:

```json
{
  "1/3/0": 0
}
```

Path example:


Indicates how the identification state is presented to the user. This attribute contains one of the values defined in IdentifyTypeEnum. The value None must NOT be used if the device is capable of presenting its identification state using one of the other methods defined in IdentifyTypeEnum.

## Bridge Command Payload Format

The bridge accepts Matter commands in this structure:

```json
{
  "message_id": "1",
  "command": "device_command",
  "args": {
    "endpoint_id": 1,
    "cluster_id": 3,
    "command_name": "Identify",
    "payload": {},
    "timed_request_timeout_ms": 1000
  }
}
```

For Cluster 3, always use `"cluster_id": 3`. Payload keys are the command field names in lowerCamelCase. Octet-string fields are base64-encoded. `timed_request_timeout_ms` is required for timed commands and ignored otherwise.

# Command: `TriggerEffect`

## Purpose

This command allows the support of feedback to the user, such as a certain light effect. It is used to allow an implementation to provide visual feedback to the user under certain circumstances such as a color light turning green when it has successfully connected to a network. The use of this command and the effects themselves are entirely up to the implementer to use whenever a visual feedback is useful but it is not the same as and does not replace the identify mechanism used during commissioning.

## Command Identity

| Field | Value |
|---|---|
| Command ID | `64` |
| Command hex | `0x40` |
| Command name | `TriggerEffect` |
| Direction | client → server |
| Conformance | `O` |
| Response | status |
| Access | (invoke: manage) |

## Payload Fields

| ID | Field | Payload key | Type | Conformance | Constraint | Meaning |
|---:|---|---|---|---|---|---|
| 0 | `EffectIdentifier` | `effectIdentifier` | EffectIdentifierEnum | `M` | desc | Indicates the identify effect to use and contains one of the non-reserved values in EffectIdentifierEnum. All values of the EffectIdentifierEnum is supported. |
| 1 | `EffectVariant` | `effectVariant` | EffectVariantEnum | `M` | desc | Indicates which variant of the effect, indicated in the EffectIdentifier field, should be triggered. If a device does not support the given variant, it must use the default variant. |

`EffectIdentifier` values (`EffectIdentifierEnum`): `0` = Blink, `1` = Breathe, `2` = Okay, `11` = ChannelChange, `254` = FinishEffect, `255` = StopEffect

`EffectVariant` values (`EffectVariantEnum`): `0` = Default
