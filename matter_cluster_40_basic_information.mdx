# Matter Cluster 40 — Basic Information Cluster

<Callout type="info">
Matter Cluster <code>40</code>, also written as <code>0x0028</code>, is the <strong>Basic Information Cluster</strong>.
This cluster provides attributes and events for determining basic information about Nodes, which supports both Commissioning and operational determination of Node characteristics, such as Vendor ID, Product ID and serial number, which apply to the whole Node.
</Callout>

| ID | Hex | Event | Priority | Conformance | Description |

## Event `0` — `StartUp`

The StartUp event is generated by a Node as soon as reasonable after completing a boot or reboot process. The StartUp event should be the first Data Model event recorded by the Node after it completes a boot or reboot process.

| ID | Field | Type | Conformance | Meaning |
|---:|---|---|---|---|
| 0 | `SoftwareVersion` | uint32 | `M` | This field is set to the same value as the one available in the SoftwareVersion attribute. |

## Event `1` — `ShutDown`

The ShutDown event should be generated by a Node prior to any orderly shutdown sequence on a best-effort basis. When a ShutDown event is generated, it should be the last Data Model event recorded by the Node. This event should be delivered urgently to current subscribers on a best-effort basis.

This event has no fields.

## Event `2` — `Leave`

The Leave event should be generated by a Node prior to permanently leaving a given Fabric, such as when the RemoveFabric command is invoked for a given fabric, or triggered by factory reset or some other manufacturer specific action to disable or reset the operational data in the Node. When a Leave event is generated, it should be assumed that the fabric recorded in the event is no longer usable, and subsequent interactions targeting that fabric will most likely fail.

| ID | Field | Type | Conformance | Meaning |
|---:|---|---|---|---|
| 0 | `FabricIndex` | fabric-idx | `M` | This field contains the local fabric-index of the fabric which the node is about to leave. |

## Event `3` — `ReachableChanged`

This event (when supported) is generated when there is a change in the Reachable attribute. Its main use case is in the derived Bridged Device Basic Information cluster.
