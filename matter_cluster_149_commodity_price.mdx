# Matter Cluster 149 — Commodity Price Cluster

<Callout type="info">
Matter Cluster <code>149</code>, also written as <code>0x0095</code>, is the <strong>Commodity Price Cluster</strong>.
The Commodity Price Cluster provides the mechanism for communicating Gas, Energy, or Water pricing information within the premises.
</Callout>

## Cluster 149 Features

The `FeatureMap` attribute (`1/149/65532`) is a bitmap. Each bit set means the device implements that feature and the attributes and commands that depend on it.

| Bit | Code | Feature | Conformance | Meaning |
|---:|---|---|---|---|
| 0 | `FORE` | Forecasting | `O` | Forecasts upcoming pricing |

Example: `FeatureMap` = `0` means no optional feature is enabled; `1` means every feature listed above is enabled.

## Data Types

### `CommodityPriceDetailBitmap` (bitmap)

| Bit | Name | Conformance | Meaning |
|---:|---|---|---|
| 0 | `Description` | `M` | A textual description of a price; e.g. the name of a rate plan. |
| 1 | `Components` | `M` | A breakdown of the component parts of a price; e.g. generation, delivery, etc. |

### `CommodityPriceComponentStruct` (struct)

This represents a component of a given price; it is only used in the Components field.

| Field | Name | Type | Conformance | Constraint | Meaning |
|---:|---|---|---|---|---|
| 0 | `Price` | money | `M` | — | Indicates the component price of the commodity per TariffUnit, with the currency indicated by the currency of the Price field of the parent CommodityPriceStruct. |
| 1 | `Source` | TariffPriceTypeEnum | `M` | — | Indicates the source of the price component. |
| 2 | `Description` | string | `O` | max length 32 | Indicates a description of the pricing plan yielding the value of the Price field. |
| 3 | `TariffComponentID` | uint32 | `O` | — | — |

### `CommodityPriceStruct` (struct)

This represents a price over a given period.

| Field | Name | Type | Conformance | Constraint | Meaning |
|---:|---|---|---|---|---|
| 0 | `PeriodStart` | epoch-s | `M` | — | Indicates the beginning timestamp in UTC of the period covered by the price indicated in the Price field, or the price level indicated in the Price Level field, or both. |
| 1 | `PeriodEnd` | epoch-s (nullable) | `M` | min compute | Indicates the ending timestamp in UTC of the period covered by the price indicated in the Price field, or the price level indicated in the Price Level field, or both. |
| 2 | `Price` | money | `O` | — | Indicates the price of the commodity per TariffUnit. |
| 3 | `PriceLevel` | int16 | `O` | — | Indicates the tariff price level. |
| 4 | `Description` | string | `O` | max length 32 | Indicates a description of the pricing plan yielding the value of the Price field, or the Price Level field. |
| 5 | `Components` | list of CommodityPriceComponentStruct | `[Price]` | max 10 entries | Indicates a list of the components that comprise the value in the Price field. |

---

## Attribute `3` / `0x0003` — `PriceForecast`

Path example:

```text
1/149/3
```

Indicates the forecast of upcoming price changes. If the forecast is unable to be determined, this list is empty. The list entries is in time order: - All entries except the last one has a non-null PeriodEnd. - For all entries except the first one, PeriodStart is greater than the previous entry's PeriodEnd. The Description and Components fields is omitted from CommodityPriceStructs in this attribute's value.

| Property | Value |
|---|---|
| Type | list of CommodityPriceStruct |
| Conformance | `FORE` |
| Access | R (read: view) |
| Constraint | max 56 entries |

Each entry is a `CommodityPriceStruct` (see Data Types).

Example:

```json
{
  "1/149/3": []
}
```

## Bridge Command Payload Format

The bridge accepts Matter commands in this structure:

```json
{
  "message_id": "1",
  "command": "device_command",
  "args": {
    "endpoint_id": 1,
    "cluster_id": 149,
    "command_name": "GetDetailedPriceRequest",
    "payload": {},
    "timed_request_timeout_ms": 1000
  }
}
```

For Cluster 149, always use `"cluster_id": 149`. Payload keys are the command field names in lowerCamelCase. Octet-string fields are base64-encoded. `timed_request_timeout_ms` is required for timed commands and ignored otherwise.
