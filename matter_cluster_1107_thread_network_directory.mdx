# Matter Cluster 1107 — Thread Network Directory Cluster

<Callout type="info">
Matter Cluster <code>1107</code>, also written as <code>0x0453</code>, is the <strong>Thread Network Directory Cluster</strong>.
This cluster stores a list of Thread networks (including the credentials required to access each network), as well as a designation of the user's preferred network, to facilitate the sharing of Thread networks across fabrics.
</Callout>

## Attribute `1` / `0x0001` — `ThreadNetworks`

Path example:

```text
1/1107/1
```

Indicates the list of Thread Networks known about by this cluster. If the node hosting this cluster includes a Thread Border Router, then an entry for its Thread Network is included in this list. The list can be modified via the AddNetwork and RemoveNetwork commands. For each entry in the list, the cluster server also stores a Thread Operational Dataset.

| Property | Value |
|---|---|
| Type | list of ThreadNetworkStruct |
| Conformance | `M` |
| Access | R (read: view) |
| Qualities | persisted |
| Constraint | max ThreadNetworkTableSize entries |

Each entry is a `ThreadNetworkStruct` (see Data Types).

Example:

```json
{
  "1/1107/1": []
}
```

## Attribute `2` / `0x0002` — `ThreadNetworkTableSize`

Path example:

```text

```

Indicates the maximum number of entries that can be held in the ThreadNetworks list; it is at least 2 times the number of SupportedFabrics advertised in the Operational Credentials Cluster on the root endpoint of this node.

```json
  "args": {
    "endpoint_id": 1,

    "command_name": "AddNetwork",
    "payload": {},
    "timed_request_timeout_ms": 1000
  }
}
```

For Cluster 1107, always use `"cluster_id": 1107`. Payload keys are the command field names in lowerCamelCase. Octet-string fields are base64-encoded. `timed_request_timeout_ms` is required for timed commands and ignored otherwise.

# Command: `AddNetwork`

## Purpose

Adds an entry to the ThreadNetworks attribute with the specified Thread Operational Dataset. If there is an existing entry with the Extended PAN ID then the Thread Operational Dataset for that entry is replaced. As a result, changes to the network parameters (e.g. Channel, Network Name, PSKc, ...) of an existing entry with a given Extended PAN ID can be made using this command.

## Command Identity

| Field | Value |
|---|---|
| Command ID | `0` |
| Command hex | `0x00` |
| Command name | `AddNetwork` |
| Direction | client → server |
| Conformance | `M` |
| Response | status |
| Access | (invoke: manage, timed) |

## Payload Fields

| ID | Field | Payload key | Type | Conformance | Constraint | Meaning |
|---:|---|---|---|---|---|---|
| 0 | `OperationalDataset` | `operationalDataset` | octstr | `M` | max length 254 | This field represents the Operational Dataset for the network, using the encoding defined in the Thread specification. |

## Bridge Command Example

```json
{
  "message_id": "1",
  "command": "device_command",
  "args": {
    "endpoint_id": 1,
    "cluster_id": 1107,
    "command_name": "AddNetwork",
    "payload": {
      "operationalDataset": "AQID"
    },
    "timed_request_timeout_ms": 1000
  }
}
```

This is a **timed command**: the bridge must send it inside a timed interaction, so `timed_request_timeout_ms` is required.
