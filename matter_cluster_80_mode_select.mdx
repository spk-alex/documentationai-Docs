# Matter Cluster 80 — Mode Select Cluster

<Callout type="info">
Matter Cluster <code>80</code>, also written as <code>0x0050</code>, is the <strong>Mode Select Cluster</strong>.
This cluster provides an interface for controlling a characteristic of a device that can be set to one of several predefined values. For example, the light pattern of a disco ball, the mode of a massage chair, or the wash cycle of a laundry machine. The server allows the client to set a mode on the server.
</Callout>

The `FeatureMap` attribute (`1/80/65532`) is a bitmap. Each bit set means the device implements that feature and the attributes and commands that depend on it.

| Bit | Code | Feature | Conformance | Meaning |
|---:|---|---|---|---|
| 0 | `DEPONOFF` | OnOff | `O` | Dependency with the OnOff cluster |

Example: `FeatureMap` = `0` means no optional feature is enabled; `1` means every feature listed above is enabled.

# Attribute Details

## Attribute `0` / `0x0000` — `Description`

Path example:

```text
1/80/0
```

This attribute describes the purpose of the server, in readable text. For example, a coffee machine may have a Mode Select cluster for the amount of milk to add, and another Mode Select cluster for the amount of sugar to add. In this case, the first instance can have the description Milk and the second instance can have the description Sugar. This allows the user to tell the purpose of each of the instances.

## Attribute `4` / `0x0004` — `StartUpMode`

Path example:

```text
1/80/4
```

The StartUpMode attribute value indicates the desired startup mode for the server when it is supplied with power. If this attribute is not null, the CurrentMode attribute is set to the StartUpMode value, when the server is powered up, except in the case when the OnMode attribute overrides the StartUpMode attribute. This behavior does not apply to reboots associated with OTA. After an OTA restart, the CurrentMode attribute returns to its value prior to the restart.

## Bridge Command Payload Format

The bridge accepts Matter commands in this structure:

```json
{
  "message_id": "1",
  "command": "device_command",
  "args": {
    "endpoint_id": 1,
    "cluster_id": 80,
    "command_name": "ChangeToMode",
    "payload": {},
    "timed_request_timeout_ms": 1000
  }
}
```

For Cluster 80, always use `"cluster_id": 80`. Payload keys are the command field names in lowerCamelCase. Octet-string fields are base64-encoded. `timed_request_timeout_ms` is required for timed commands and ignored otherwise.

# Command: `ChangeToMode`

## Purpose

On receipt of this command, if the NewMode field indicates a valid mode transition within the supported list, the server must set the CurrentMode attribute to the NewMode value, otherwise, the server must respond with an INVALID_COMMAND status response.
