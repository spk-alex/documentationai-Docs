# Matter Cluster 2049 — TLS Certificate Management Cluster

<Callout type="info">
Matter Cluster <code>2049</code>, also written as <code>0x0801</code>, is the <strong>TLS Certificate Management Cluster</strong>.
This cluster is used to manage TLS CA Root and Client Certificates on a Node, which are then used by other clusters to provision and manage their usage of TLS. Commands in this cluster uniformly use the Large Message qualifier, even when the command doesn't require it, to reduce the testing matrix. This cluster is present on the root node endpoint when required by a device type, may be present on that endpoint otherwise, and must NOT be present on any other Endpoint of any Node.
</Callout>

## Data Types

### `TLSCertStruct` (struct) — fabric-scoped

This encodes the mapping between a TLSCAID and the associated root certificate.

| Field | Name | Type | Conformance | Constraint | Meaning |
|---:|---|---|---|---|---|
| 0 | `CAID` | TLSCAID | `M` | 0 to 65534 | — |
| 1 | `Certificate` | octstr | `O` | max length 3000 | This field is an octet string that represents a certificate encoded using DER encoding. |

### `TLSClientCertificateDetailStruct` (struct) — fabric-scoped

This encodes a TLS Client Certificate and corresponding ICAC chain.

| Field | Name | Type | Conformance | Constraint | Meaning |
|---:|---|---|---|---|---|
| 0 | `CCDID` | TLSCCDID | `M` | 0 to 65534 | — |
| 1 | `ClientCertificate` | octstr (nullable) | `O` | max length 3000 | This field is an octet string that represents a TLS Client Certificate encoded using DER encoding. |
| 2 | `IntermediateCertificates` | list of octstr | `O` | max 10 entries | This field is a list of octet strings representing one or more ICACs (also encoded using DER) that form a Certificate Chain up to, but not including, the TLSRCAC. |

## Bridge Command Payload Format

The bridge accepts Matter commands in this structure:

```json
{
  "message_id": "1",
  "command": "device_command",
  "args": {
    "endpoint_id": 0,
    "cluster_id": 2049,
    "command_name": "ProvisionRootCertificate",
    "payload": {},
    "timed_request_timeout_ms": 1000
  }
}
```

For Cluster 2049, always use `"cluster_id": 2049`. Payload keys are the command field names in lowerCamelCase. Octet-string fields are base64-encoded. `timed_request_timeout_ms` is required for timed commands and ignored otherwise.

# SmartphoneKey Notes

- Cluster 2049 is **not currently exposed by SmartphoneKey devices**. This page documents the Matter 1.6.1 specification so that future devices can be interpreted without changes to the backend.
- Shadow paths follow `endpoint/2049/attribute`; attribute values that the device reports as unreadable are written as `n/a`.
