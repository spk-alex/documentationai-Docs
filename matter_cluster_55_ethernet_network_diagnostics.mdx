# Matter Cluster 55 — Ethernet Network Diagnostics Cluster

<Callout type="info">
Matter Cluster <code>55</code>, also written as <code>0x0037</code>, is the <strong>Ethernet Network Diagnostics Cluster</strong>.
The Ethernet Network Diagnostics Cluster provides a means to acquire standardized diagnostics metrics that may be used by a Node to assist a user or Administrator in diagnosing potential problems. The Ethernet Network Diagnostics Cluster attempts to centralize all metrics that are relevant to a potential Ethernet connection to a Node.
</Callout>

## Cluster 55 Features

The `FeatureMap` attribute (`0/55/65532`) is a bitmap. Each bit set means the device implements that feature and the attributes and commands that depend on it.

| Bit | Code | Feature | Conformance | Meaning |
|---:|---|---|---|---|
| 0 | `PKTCNT` | PacketCounts | `O` | Node makes available the counts for the number of received and transmitted packets on the ethernet interface |
| 1 | `ERRCNT` | ErrorCounts | `O` | Node makes available the counts for the number of errors that have occurred during the reception and transmission of packets on the ethernet interface |

Example: `FeatureMap` = `0` means no optional feature is enabled; `3` means every feature listed above is enabled.

## Bridge Command Payload Format

The bridge accepts Matter commands in this structure:

```json
{
  "message_id": "1",
  "command": "device_command",
  "args": {
    "endpoint_id": 0,
    "cluster_id": 55,
    "command_name": "ResetCounts",
    "payload": {},
    "timed_request_timeout_ms": 1000
  }
}
```

For Cluster 55, always use `"cluster_id": 55`. Payload keys are the command field names in lowerCamelCase. Octet-string fields are base64-encoded. `timed_request_timeout_ms` is required for timed commands and ignored otherwise.

# Command: `ResetCounts`

## Purpose

This command is used to reset the count attributes. Reception of this command must reset the following attributes to 0: - PacketRxCount - PacketTxCount - TxErrCount - CollisionCount - OverrunCount
