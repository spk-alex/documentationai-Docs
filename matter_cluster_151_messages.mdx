# Matter Cluster 151 — Messages Cluster

<Callout type="info">
Matter Cluster <code>151</code>, also written as <code>0x0097</code>, is the <strong>Messages Cluster</strong>.
This cluster provides an interface for passing messages to be presented by a device.
</Callout>

## Cluster 151 Features

The `FeatureMap` attribute (`1/151/65532`) is a bitmap. Each bit set means the device implements that feature and the attributes and commands that depend on it.

| Bit | Code | Feature | Conformance | Meaning |
|---:|---|---|---|---|
| 0 | `CONF` | ReceivedConfirmation | `O` | This feature indicates that the device can get confirmation from a user that the message was received. |
| 1 | `RESP` | ConfirmationResponse | `[CONF]` | This feature indicates that the device is capable of presenting a list of responses to the user and recording the user's choice of response. |
| 2 | `RPLY` | ConfirmationReply | `[CONF]` | This feature indicates that the device is capable of collecting a free-form text response to a message. |
| 3 | `PROT` | ProtectedMessages | `O` | This feature indicates that the device is capable of requiring the user to authenticate before viewing a message; e.g. entering a PIN or password before viewing a message with billing information. |

Example: `FeatureMap` = `0` means no optional feature is enabled; `15` means every feature listed above is enabled.

## Attribute `0` / `0x0000` — `Messages`

## Bridge Command Payload Format

The bridge accepts Matter commands in this structure:

```json
{
  "message_id": "1",
  "command": "device_command",
  "args": {
    "endpoint_id": 1,
    "cluster_id": 151,
    "command_name": "PresentMessagesRequest",
    "payload": {},
    "timed_request_timeout_ms": 1000
  }
}
```

For Cluster 151, always use `"cluster_id": 151`. Payload keys are the command field names in lowerCamelCase. Octet-string fields are base64-encoded. `timed_request_timeout_ms` is required for timed commands and ignored otherwise.

# Command: `PresentMessagesRequest`

## Purpose

On receipt, this must cause the message in the passed fields to be appended to the Messages attribute. If appending the message would cause the number of messages to be greater than the capacity of the list, the device must NOT append any message to Messages, and returns a status code of RESOURCE_EXHAUSTED. When displaying a message in response to this command, an indication (ex. visual) of the origin node of the command is provided. This could be in the form of a friendly name label which uniquely identifies the node to the user.
