# Matter Cluster 514 — Fan Control Cluster

<Callout type="info">
Matter Cluster <code>514</code>, also written as <code>0x0202</code>, is the <strong>Fan Control Cluster</strong>.
This cluster specifies an interface to control the speed of a fan.
</Callout>


Indicates the current speed mode of the fan. This attribute is set to one of the values in FanModeEnum supported by the server as indicated in the FanModeSequence attribute. ## Attribute `3` / `0x0003` — `PercentCurrent`

Path example:

```text
1/514/3
```

Indicates the actual currently operating fan speed, or zero to indicate that the fan is off. There may be a temporary mismatch between the value of this attribute and the value of the PercentSetting attribute due to other system requirements or constraints that would not allow the fan to operate at the requested setting. For example, if the value of this attribute is currently 50%, and the PercentSetting attribute is newly set to 25%, the value of this attribute may stay above 25% for a period necessary to dissipate internal heat, maintain product operational safety, etc.

## Attribute `8` / `0x0008` — `RockSetting`

Path example:

```text
1/514/8
```

This attribute is a bitmap that indicates the currently active fan rocking motion setting. Each bit only be set to 1, if the corresponding bit in the RockSupport attribute is set to 1, otherwise a status code of CONSTRAINT_ERROR is returned. If a combination of supported bits is set by a client, and the server does not support the combination, the lowest supported single bit in the combination is set and active, and all other bits indicates zero. For example: If RockUpDown and RockRound are both set, but this combination is not possible, then only RockUpDown becomes active.

## Bridge Command Payload Format

The bridge accepts Matter commands in this structure:

```json
{
  "message_id": "1",
  "command": "device_command",
  "args": {
    "endpoint_id": 1,
    "cluster_id": 514,
    "command_name": "Step",
    "payload": {},
    "timed_request_timeout_ms": 1000
  }
}
```

For Cluster 514, always use `"cluster_id": 514`. Payload keys are the command field names in lowerCamelCase. Octet-string fields are base64-encoded. `timed_request_timeout_ms` is required for timed commands and ignored otherwise.

# Command: `Step`

## Purpose

This command indirectly changes the speed-oriented attributes of the fan in steps rather than using the speed-oriented attributes, FanMode, PercentSetting, or SpeedSetting, directly. This command supports, for example, a user-operated and wall-mounted toggle switch that can be used to increase or decrease the speed of the fan by pressing the toggle switch up or down until the desired fan speed is reached. How this command is interpreted by the server and how it affects the values of the speed-oriented attributes is implementation specific. For example, a fan supports this command, and the value of the FanModeSequence attribute is 0.

## Command Identity

| Field | Value |
|---|---|
| Command ID | `0` |
| Command hex | `0x00` |
| Command name | `Step` |
| Direction | client → server |
| Conformance | `STEP` |
| Response | status |
| Access | (invoke: operate) |

## Payload Fields

| ID | Field | Payload key | Type | Conformance | Constraint | Meaning |
|---:|---|---|---|---|---|---|
| 0 | `Direction` | `direction` | StepDirectionEnum | `M` | — | Indicates whether the speed-oriented attributes increase or decrease to the next step value. |
| 1 | `Wrap` | `wrap` | bool | `O` | — | Indicates if the speed-oriented attributes wrap between highest and lowest step value. |
| 2 | `LowestOff` | `lowestOff` | bool | `O` | — | Indicates that the fan being off (FanMode = Off, PercentSetting = 0, or SpeedSetting = 0) is included as a step value. |

`Direction` values (`StepDirectionEnum`): `0` = Increase, `1` = Decrease
