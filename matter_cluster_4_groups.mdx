# Matter Cluster 4 — Groups Cluster

<Callout type="info">
Matter Cluster <code>4</code>, also written as <code>0x0004</code>, is the <strong>Groups Cluster</strong>.
Starting with the release of Matter when the Groupcast Cluster becomes certifiable, that cluster supersedes this Groups Cluster. Groups created on devices prior to that Matter release remain operational via the PerGroup feature in the Groupcast Cluster. All new group management operations should be performed through the Groupcast Cluster.
</Callout>

## Cluster 4 Features

The `FeatureMap` attribute (`1/4/65532`) is a bitmap. Each bit set means the device implements that feature and the attributes and commands that depend on it.

| Bit | Code | Feature | Conformance | Meaning |
|---:|---|---|---|---|
| 0 | `GN` | GroupNames | `O` | The ability to store a name for a group |

Example: `FeatureMap` = `0` means no optional feature is enabled; `1` means every feature listed above is enabled.

# Attribute Details

## Attribute `0` / `0x0000` — `NameSupport`

Path example:

```text
1/4/0
```

This attribute provides legacy, read-only access to whether the Group Names feature is supported. The most significant bit, bit 7 (GroupNames), is equal to bit 0 of the FeatureMap attribute (GN Feature). All other bits is 0.

| Property | Value |
|---|---|
| Type | NameSupportBitmap |
| Conformance | `M` |
| Access | R (read: view) |
| Constraint | desc |

Bits (`NameSupportBitmap`):

| Bit | Name | Meaning |
|---:|---|---|
| 7 | `GroupNames` | The ability to store a name for a group. |

Example:

```json
{
  "1/4/0": 0
}
```

</Callout>

## Bridge Command Payload Format

The bridge accepts Matter commands in this structure:

```json
{
  "message_id": "1",
  "command": "device_command",
  "args": {
    "endpoint_id": 1,
    "cluster_id": 4,
    "command_name": "AddGroup",
    "payload": {},
    "timed_request_timeout_ms": 1000
  }
}
```

For Cluster 4, always use `"cluster_id": 4`. Payload keys are the command field names in lowerCamelCase. Octet-string fields are base64-encoded. `timed_request_timeout_ms` is required for timed commands and ignored otherwise.

# Command: `AddGroupIfIdentifying`

## Purpose

The AddGroupIfIdentifying command allows a client to add group membership in a particular group for the server endpoint, on condition that the endpoint is identifying itself. Identifying functionality is controlled using the Identify cluster,. For correct operation of the AddGroupIfIdentifying command, any endpoint that supports the Groups server cluster must also support the Identify server cluster. This command might be used to assist configuring group membership in the absence of a commissioning tool.
