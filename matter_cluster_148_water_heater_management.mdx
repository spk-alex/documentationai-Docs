# Matter Cluster 148 — Water Heater Management Cluster

<Callout type="info">
Matter Cluster <code>148</code>, also written as <code>0x0094</code>, is the <strong>Water Heater Management Cluster</strong>.
This cluster is used to allow clients to control the operation of a hot water heating appliance so that it can be used with energy management. Heating of hot water is one of the main energy uses in homes, and when coupled with the Energy Management cluster, it can help consumers save cost (e.g. using power at cheaper times or from local solar PV generation).
</Callout>

## Attribute `4` / `0x0004` — `TankPercentage`

Path example:

```text
1/148/4
```

Indicates an approximate level of hot water stored in the tank, which might help consumers understand the amount of hot water remaining in the tank. The accuracy of this attribute is manufacturer specific. In most hot water tanks, there is a stratification effect where the hot water layer rests above a cooler layer of water below. For this reason cold water is fed in at the bottom of the tank and the hot water is drawn from the top.

| Property | Value |
|---|---|
| Type | percent |
| Conformance | `TP` |
| Access | R (read: view) |

Example:

```json
{
  "1/148/4": 1
}
```

## Bridge Command Payload Format

The bridge accepts Matter commands in this structure:

```json
{
  "message_id": "1",
  "command": "device_command",
  "args": {
    "endpoint_id": 1,
    "cluster_id": 148,
    "command_name": "Boost",
    "payload": {},
    "timed_request_timeout_ms": 1000
  }
}
```

For Cluster 148, always use `"cluster_id": 148`. Payload keys are the command field names in lowerCamelCase. Octet-string fields are base64-encoded. `timed_request_timeout_ms` is required for timed commands and ignored otherwise.
