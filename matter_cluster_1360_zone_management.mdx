# Matter Cluster 1360 — Zone Management Cluster

<Callout type="info">
Matter Cluster <code>1360</code>, also written as <code>0x0550</code>, is the <strong>Zone Management Cluster</strong>.
This cluster provides an interface to manage regions of interest, or Zones, which can be either manufacturer or user defined. This cluster also defines a Trigger, which is a set of conditions and timing that apply to a Zone and allow for events to be generated or the triggering state to be used by other clusters such as Push AV Stream Transport Cluster.
</Callout>

## Cluster 1360 Features

The `FeatureMap` attribute (`1/1360/65532`) is a bitmap. Each bit set means the device implements that feature and the attributes and commands that depend on it.

| Bit | Code | Feature | Conformance | Meaning |
|---:|---|---|---|---|
| 0 | `TWODCART` | TwoDimensionalCartesianZone | `O` | Supports Two Dimensional Cartesian Zones |
| 1 | `PERZONESENS` | PerZoneSensitivity | `[TWODCART]` | Supports a sensitivity value per Zone |
| 2 | `USERDEFINED` | UserDefined | `[TWODCART]` | Supports user defined zones |
| 3 | `FOCUSZONES` | FocusZones | `[USERDEFINED]` | Supports user defined focus zones |

Example: `FeatureMap` = `0` means no optional feature is enabled; `15` means every feature listed above is enabled.

| 1 | `Y` | uint16 | `M` | — | This field represents the position of the vertex along the vertical (y) axis. |

### `TwoDCartesianZoneStruct` (struct)

This struct is used to encode all information needed to define a TwoDCartesianZone.

| Field | Name | Type | Conformance | Constraint | Meaning |
|---:|---|---|---|---|---|
| 0 | `Name` | string | `M` | max length 32 | The Name field is a string representing the name of the Zone. |
| 1 | `Use` | ZoneUseEnum | `M` | — | The Use field is a Zone Use Enum representing the purpose of the Zone. |
| 2 | `Vertices` | list of TwoDCartesianVertexStruct | `M` | 3 to 12 entries | The Vertices field is a list of vertices of type TwoDCartesianVertexStruct. |
| 3 | `Color` | string | `O` | allowed: 7, 9 | Indicates the color, in RGB or RGBA, used for attaching a color to the Zone definition and is a purely informational value to help in uniformly presenting Zones in User Interfaces and may be ignored. |

### `ZoneInformationStruct` (struct)

This struct is used to encode basic information about a Zone without containing the specifics of how the zone is defined.

| Field | Name | Type | Conformance | Constraint | Meaning |
|---:|---|---|---|---|---|
| 0 | `ZoneID` | ZoneID | `M` | — | — |
| 1 | `ZoneType` | ZoneTypeEnum | `M` | — | Indicates the zone type which defines the Zone. |
| 2 | `ZoneSource` | ZoneSourceEnum | `M` | — | Indicates the source of the Zone. |
| 3 | `TwoDCartesianZone` | TwoDCartesianZoneStruct | `TWODCART & ZoneType = TwoDCARTZone` | — | Indicates the detailed information for the TwoDCartesianZone. |

### `ZoneTriggerControlStruct` (struct)

This struct is used to encode a set of values for controlling the generation of ZoneTriggered and ZoneStopped events from the Node. Zone events can be triggered due to many underlying reasons, such as a motion sensor on the device, and this is intended to be manufacturer-specific.

| Field | Name | Type | Conformance | Constraint | Meaning |
|---:|---|---|---|---|---|
| 0 | `ZoneID` | ZoneID | `M` | — | — |
| 1 | `InitialDuration` | elapsed-s | `M` | 1 to 65535 | Indicates the initial duration in seconds after triggering activity is first detected before the Node could generate a ZoneStopped event. |
| 2 | `AugmentationDuration` | elapsed-s | `M` | max InitialDuration | Indicates the duration in seconds that the TriggerDetectedDuration value is to be extended by if the triggering activity is still detected during this period. |
| 3 | `MaxDuration` | elapsed-s | `M` | min InitialDuration | Indicates the maximum duration in seconds after the initial triggering activity detection that additional triggering activity will be detected. |
| 4 | `BlindDuration` | elapsed-s | `M` | — | Indicates the duration in seconds after a ZoneStopped event is generated that the Node must NOT generate any ZoneTriggered events. |
| 5 | `Sensitivity` | uint8 | `PERZONESENS` | 1 to SensitivityMax | Indicates the per-zone sensitivity of the underlying zone triggering detection mechanism. |

## Attribute `4` / `0x0004` — `SensitivityMax`

Path example:

```text
1/1360/4
```

This attribute specifies the hardware specific value for the number of supported sensitivity levels. This value is manufacturer defined. If the PerZoneSensitivity feature is supported, the value of this attribute determines valid values for the Sensitivity field in ZoneTriggerControlStruct; if the PerZoneSensitivity feature is not supported, the value of this attribute determines valid values for the Sensitivity Attribute. Implementations require two to ten levels of sensitivity control in order to ensure that there is some user-level customization of the Trigger.

## Bridge Command Payload Format

The bridge accepts Matter commands in this structure:

```json
{
  "message_id": "1",
  "command": "device_command",
  "args": {
    "endpoint_id": 1,
    "cluster_id": 1360,
    "command_name": "CreateTwoDCartesianZone",
    "payload": {},
    "timed_request_timeout_ms": 1000
  }
}
```

For Cluster 1360, always use `"cluster_id": 1360`. Payload keys are the command field names in lowerCamelCase. Octet-string fields are base64-encoded. `timed_request_timeout_ms` is required for timed commands and ignored otherwise.
