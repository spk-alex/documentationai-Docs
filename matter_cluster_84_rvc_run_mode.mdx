# Matter Cluster 84 — RVC Run Mode Cluster

<Callout type="info">
Matter Cluster <code>84</code>, also written as <code>0x0054</code>, is the <strong>RVC Run Mode Cluster</strong>.
This cluster is derived from the Mode Base cluster and defines additional mode tags and namespaced enumerated values for the running modes of robotic vacuum cleaner devices.
</Callout>

<Callout type="info">
This cluster is <strong>derived from the Mode Base cluster</strong>: it inherits the base attributes, commands and data types listed below and adds the cluster-specific values. Where the base definition applies, the base text is used.
</Callout>

### Revision history

| Revision | Change |
|---:|---|
| 1 | Initial revision |
| 2 | Add constraint about switching from non-Idle to non-Idle modes. ChangeToModeResponse command: StatusText must be provided for InvalidInMode status. Deprecate the OnMode attribute and the related feature map bit. Add the Mapping mode tag. |

## Cluster 84 Features

The `FeatureMap` attribute (`1/84/65532`) is a bitmap. Each bit set means the device implements that feature and the attributes and commands that depend on it.

| Bit | Code | Feature | Conformance | Meaning |
|---:|---|---|---|---|
| 0 | `DEPONOFF` | OnOff | `X` | Dependency with the OnOff cluster |
| 20 | `DIRECTMODECH` | DirectModeChange | `O` | Cluster supports changing run modes from non-Idle states |

Example: `FeatureMap` = `0` means no optional feature is enabled; `1048577` means every feature listed above is enabled.

## Attribute `0` / `0x0000` — `SupportedModes`

Path example:

```text

At least one entry in the SupportedModes attribute (different from the one above) includes the Cleaning mode tag in the ModeTags field. The Mapping, Cleaning, and Idle mode tags are mutually exclusive and must NOT be used together in a mode's ModeTags.

## Bridge Command Payload Format

The bridge accepts Matter commands in this structure:

```json
{
  "message_id": "1",
  "command": "device_command",
  "args": {
    "endpoint_id": 1,
    "cluster_id": 84,
    "command_name": "ChangeToMode",
    "payload": {},
    "timed_request_timeout_ms": 1000
  }
}
```

For Cluster 84, always use `"cluster_id": 84`. Payload keys are the command field names in lowerCamelCase. Octet-string fields are base64-encoded. `timed_request_timeout_ms` is required for timed commands and ignored otherwise.

# Command: `ChangeToMode`

## Purpose

This command is used to change device modes. On receipt of this command the device must respond with a ChangeToModeResponse command.

```json
