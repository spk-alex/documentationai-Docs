# Matter Cluster 44 — Time Format Localization Cluster

<Callout type="info">
Matter Cluster <code>44</code>, also written as <code>0x002C</code>, is the <strong>Time Format Localization Cluster</strong>.
Nodes should be expected to be deployed to any and all regions of the world. These global regions may have differing preferences for how dates and times are conveyed. As such, Nodes that visually or audibly convey time information need a mechanism by which they can be configured to use a user’s preferred format.
</Callout>

## Cluster 44 Features

The `FeatureMap` attribute (`0/44/65532`) is a bitmap. Each bit set means the device implements that feature and the attributes and commands that depend on it.

| Bit | Code | Feature | Conformance | Meaning |
|---:|---|---|---|---|
| 0 | `CALFMT` | CalendarFormat | `O` | The Node can be configured to use different calendar formats when conveying values to a user |

Example: `FeatureMap` = `0` means no optional feature is enabled; `1` means every feature listed above is enabled.

# Attribute Details

## Attribute `0` / `0x0000` — `HourFormat`

Path example:

```text
0/44/0
```

Indicates the format that the Node is currently configured to use when conveying the hour unit of time. If not UseActiveLocale, this value must take priority over any unit implied through the ActiveLocale attribute. If UseActiveLocale, any unit implied through the ActiveLocale attribute is used as the hour format, and if ActiveLocale is not present, the hour format is unknown.

| Property | Value |
|---|---|
| Type | HourFormatEnum |
| Conformance | `M` |
| Access | R/W (read: view, write: manage) |
| Qualities | persisted |

Values (`HourFormatEnum`):

| Value | Name | Meaning |
|---:|---|---|
| 0 | `12hr` | Time conveyed with a 12-hour clock |
| 1 | `24hr` | Time conveyed with a 24-hour clock |
| 255 | `UseActiveLocale` | Use active locale clock |

Example:

```json
{
  "0/44/0": 0
}
```

## Attribute `2` / `0x0002` — `SupportedCalendarTypes`

Path example:

```text
0/44/2
```

Indicates a list of CalendarTypeEnum values that are supported by the Node. The list must NOT contain any duplicate entries. The ordering of items within the list should NOT express any meaning. The maximum length of the SupportedCalendarTypes list is equivalent to the number of enumerations within CalendarTypeEnum.

| Property | Value |
|---|---|
| Type | list of CalendarTypeEnum |
| Conformance | `CALFMT` |
| Access | R (read: view) |
| Constraint | desc |

Example:

```json
{
  "0/44/2": []
}
```
