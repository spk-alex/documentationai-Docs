# Matter Cluster 41 — OTA Software Update Provider Cluster

<Callout type="info">
Matter Cluster <code>41</code>, also written as <code>0x0029</code>, is the <strong>OTA Software Update Provider Cluster</strong>.
This cluster implements the Provider role in the OTA process.
</Callout>

## Cluster Identity

| Field | Value |
|---|---|
| Cluster ID decimal | `41` |
| Cluster ID hex | `0x0029` |
| Cluster name | `OTA Software Update Provider` |
| Cluster revision (Matter 1.6.1) | `1` |
| Role | utility |
| Scope | Node |
| PICS code | `OTAP` |
| Typical endpoint | `0` |

### Revision history

| Revision | Change |
|---:|---|
| 1 | Initial revision |

## Data Types

### `ApplyUpdateActionEnum`

This enumeration is used in the Action field of the ApplyUpdateResponse command. See (Action).

| Value | Name | Conformance | Meaning |
|---:|---|---|---|
| 0 | `Proceed` | `M` | Apply the update. |
| 1 | `AwaitNextAction` | `M` | Wait at least the given delay time. |
| 2 | `Discontinue` | `M` | The OTA Provider is conveying a desire to rescind a previously provided Software Image. |

### `DownloadProtocolEnum`

Note that only HTTP over TLS (HTTPS) is supported. Using HTTP without TLS must NOT be supported, as there is no way to authenticate the involved participants.

| Value | Name | Conformance | Meaning |
|---:|---|---|---|
| 0 | `BDXSynchronous` | `M` | Indicates support for synchronous BDX. |
| 1 | `BDXAsynchronous` | `O` | Indicates support for asynchronous BDX. |
| 2 | `HTTPS` | `O` | Indicates support for HTTPS. |
| 3 | `VendorSpecific` | `O` | Indicates support for vendor specific protocol. |

### `StatusEnum`

| Value | Name | Conformance | Meaning |
|---:|---|---|---|
| 0 | `UpdateAvailable` | `M` | Indicates that the OTA Provider has an update available. |
| 1 | `Busy` | `M` | Indicates OTA Provider may have an update, but it is not ready yet. |
| 2 | `NotAvailable` | `M` | Indicates that there is definitely no update currently available from the OTA Provider. |
| 3 | `DownloadProtocolNotSupported` | `M` | Indicates that the requested download protocol is not supported by the OTA Provider. |

## Bridge Command Payload Format

The bridge accepts Matter commands in this structure:

```json
{
  "message_id": "1",
  "command": "device_command",
  "args": {
    "endpoint_id": 0,
    "cluster_id": 41,
    "command_name": "QueryImage",
    "payload": {},
    "timed_request_timeout_ms": 1000
  }
}
```

For Cluster 41, always use `"cluster_id": 41`. Payload keys are the command field names in lowerCamelCase. Octet-string fields are base64-encoded. `timed_request_timeout_ms` is required for timed commands and ignored otherwise.

# Command: `QueryImage`

## Purpose

On receipt, this command must trigger an attempt to find an updated Software Image by the OTA Provider to match the OTA Requestor's constraints provided in the payload fields.

## Command Identity

| Field | Value |
|---|---|
| Command ID | `0` |
| Command hex | `0x00` |
| Command name | `QueryImage` |
| Direction | client → server |
| Conformance | `M` |
| Response | QueryImageResponse |
| Access | (invoke: operate) |

## Payload Fields

| ID | Field | Payload key | Type | Conformance | Constraint | Meaning |
|---:|---|---|---|---|---|---|
| 0 | `VendorID` | `vendorID` | vendor-id | `M` | — | — |
| 1 | `ProductID` | `productID` | uint16 | `M` | — | — |
| 2 | `SoftwareVersion` | `softwareVersion` | uint32 | `M` | — | The SoftwareVersion included in the request payload provides the value representing the current version running on the OTA Requestor invoking the command. This version is equal to the Software Version attribute of the Basic Information Cluster. |
| 3 | `ProtocolsSupported` | `protocolsSupported` | list of DownloadProtocolEnum | `M` | max 8 entries | This field contains a list of all download protocols supported by the OTA Requestor. This field is used by the OTA Provider to generate the correct URI for the location of the Software Image when one is found to be available. |
| 4 | `HardwareVersion` | `hardwareVersion` | uint16 | `O` | — | The value of this field, if present, contains the OTA Requestor's hardware version, and is equal to the HardwareVersion attribute of the Basic Information Cluster. |
| 5 | `Location` | `location` | string | `O` | allowed: 2 | The location, if present, provides the same value as the Basic Information Cluster Location attribute for the OTA Requestor as configured. This may be used by the OTA Provider logic to allow per-region selection of the Software Image. |
| 6 | `RequestorCanConsent` | `requestorCanConsent` | bool | `O` | — | This field is set to true by an OTA Requestor that is capable of obtaining user consent for OTA application by virtue of built-in user interface capabilities. |
| 7 | `MetadataForProvider` | `metadataForProvider` | octstr | `O` | max length 512 | This optional field, if present, must consist of a top-level anonymous list; each list element has a profile-specific tag encoded in fully-qualified form. |

## Bridge Command Example

```json
{
  "message_id": "1",
  "command": "device_command",
  "args": {
    "endpoint_id": 0,
    "cluster_id": 41,
    "command_name": "QueryImage",
```
