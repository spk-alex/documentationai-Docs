# Matter Cluster 153 — Energy EVSE Cluster

<Callout type="info">
Matter Cluster <code>153</code>, also written as <code>0x0099</code>, is the <strong>Energy EVSE Cluster</strong>.
Electric Vehicle Supply Equipment (EVSE) is equipment used to charge an Electric Vehicle (EV) or Plug-In Hybrid Electric Vehicle. This cluster provides an interface to the functionality of Electric Vehicle Supply Equipment (EVSE) management. Devices targeted by this cluster include Electric Vehicle Supply Equipment (EVSE).
</Callout>

## Cluster 153 Features

The `FeatureMap` attribute (`1/153/65532`) is a bitmap. Each bit set means the device implements that feature and the attributes and commands that depend on it.

| Bit | Code | Feature | Conformance | Meaning |
|---:|---|---|---|---|
| 0 | `PREF` | ChargingPreferences | `M` | EVSE supports storing user charging preferences |
| 1 | `SOC` | SoCReporting | `O` | EVSE supports reporting of vehicle State of Charge (SoC) |
| 2 | `PNC` | PlugAndCharge | `O` | EVSE supports PLC to support Plug and Charge |
| 3 | `RFID` | RFID | `O` | EVSE is fitted with an RFID reader |
| 4 | `V2X` | V2X | `O` | EVSE supports bi-directional charging / discharging |

Example: `FeatureMap` = `0` means no optional feature is enabled; `31` means every feature listed above is enabled.

# Attribute Details

## Attribute `0` / `0x0000` — `State`

Path example:

```text
1/153/0
```

Indicates the current status of the EVSE. This higher-level status is partly derived from the signaling protocol as communicated between the EVSE and the vehicle through the pilot signal. The State attribute must change when the EVSE detects change of condition of the EV (plugged in or unplugged, whether the vehicle is asking for demand or not, and if it is charging or discharging). SessionEnding is not really a state but a transition.

|---|---|
| Type | StateEnum |
| Conformance | `M` |
| Access | R (read: view) |
| Qualities | nullable |

## Bridge Command Payload Format

The bridge accepts Matter commands in this structure:

```json
{
  "message_id": "1",
  "command": "device_command",
  "args": {
    "endpoint_id": 1,
    "cluster_id": 153,
    "command_name": "Disable",
    "payload": {},
    "timed_request_timeout_ms": 1000
  }
}
```

For Cluster 153, always use `"cluster_id": 153`. Payload keys are the command field names in lowerCamelCase. Octet-string fields are base64-encoded. `timed_request_timeout_ms` is required for timed commands and ignored otherwise.

## Event `2` — `EnergyTransferStarted`

This event is generated whenever the EV starts charging or discharging, except when an EV has switched between charging and discharging under the control of the PowerAdjustment feature of the Device Energy Management cluster of the associated Device Energy Management device.

| ID | Field | Type | Conformance | Meaning |
|---:|---|---|---|---|
| 0 | `SessionID` | uint32 | `M` | — |
| 1 | `State` | StateEnum | `M` | Indicates the value of the State attribute at the time the event was generated. |
| 2 | `MaximumCurrent` | amperage-mA | `M` | Indicates the value of the maximum charging current at the time the event was generated. A non-zero value indicates that the EV has been enabled for charging and the value is taken directly from the MaximumChargeCurrent attribute. |
| 3 | `MaximumDischargeCurrent` | amperage-mA | `V2X` | Indicates the value of the maximum discharging current at the time the event was generated. A non-zero value indicates that the EV has been enabled for discharging and the value is taken directly from the MaximumDischargeCurrent attribute. |

## Event `3` — `EnergyTransferStopped`

This event is generated whenever the EV stops charging or discharging, except when an EV has switched between charging and discharging under the control of the PowerAdjustment feature of the Device Energy Management cluster of the associated Device Energy Management device.

| ID | Field | Type | Conformance | Meaning |
|---:|---|---|---|---|
| 0 | `SessionID` | uint32 | `M` | — |
| 1 | `State` | StateEnum | `M` | Indicates the value of the State attribute prior to the energy transfer stopping. |
| 2 | `Reason` | EnergyTransferStoppedReasonEnum | `M` | Indicates the reason why the energy transferred stopped. |
| 4 | `EnergyTransferred` | energy-mWh | `M` | Indicates the amount of energy transferred from the EVSE to the EV since the previous EnergyTransferStarted event, in mWh. |
| 5 | `EnergyDischarged` | energy-mWh | `V2X` | Indicates the amount of energy transferred from the EV to the EVSE since the previous EnergyTransferStarted event, in mWh. |

## Event `4` — `Fault`

If the EVSE detects a fault it must generate a Fault Event. The SupplyState attribute is set to DisabledError and the type of fault detected by the EVSE is stored in the FaultState attribute. This event is generated when the FaultState changes from any error state. i.e. if it changes from NoError to any other state and if the error then clears, this would generate 2 events.

| ID | Field | Type | Conformance | Meaning |
|---:|---|---|---|---|
| 0 | `SessionID` | uint32 (nullable) | `M` | — |
| 1 | `State` | StateEnum | `M` | Indicates the value of the State attribute prior to the Fault State being changed. |
| 2 | `FaultStatePreviousState` | FaultStateEnum | `M` | Indicates the value of the FaultState attribute prior to the Fault State being changed. |
| 4 | `FaultStateCurrentState` | FaultStateEnum | `M` | Indicates the current value of the FaultState attribute. |
