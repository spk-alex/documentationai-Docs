# Matter Cluster 1292 — Application Launcher Cluster

<Callout type="info">
Matter Cluster <code>1292</code>, also written as <code>0x050C</code>, is the <strong>Application Launcher Cluster</strong>.
This cluster provides an interface for launching applications on a Video Player device such as a TV. This cluster is supported on endpoints that can launch Applications, such as a Casting Video Player device with a Content App Platform. It supports identifying an Application by global identifier from a given catalog, and launching it.
</Callout>

# Attribute Details

## Attribute `0` / `0x0000` — `CatalogList`

Path example:

```text
1/1292/0
```

This attribute specifies the list of supported application catalogs, where each entry in the list is the Connectivity Standards Alliance-issued vendor ID for the catalog. The DIAL registry must use value 0x0000. It is expected that Content App Platform providers will have their own catalog vendor ID (set to their own Vendor ID) and will assign an ApplicationID to each Content App.

| Property | Value |
|---|---|
| Type | list of uint16 |
| Conformance | `AP` |
| Access | R (read: view) |
| Qualities | persisted |

Example:

```json
{
  "1/1292/0": []
}
```

---

## Attribute `1` / `0x0001` — `CurrentApp`

Path example:

```text
1/1292/1
```

This attribute specifies the current in-focus application, identified using an Application ID, catalog vendor ID and the corresponding endpoint number when the application is represented by a Content App endpoint. A null is used to indicate there is no current in-focus application.

| Property | Value |
|---|---|
| Type | ApplicationEPStruct |
| Conformance | `O` |
| Access | R (read: view) |
| Qualities | nullable |
| Constraint | desc |
| Default | `null` |

Value is a `ApplicationEPStruct` struct (see Data Types).

Example:

```json
{
  "1/1292/1": {
    "application": {
      "catalogVendorID": 1,
      "applicationID": "example"
    },
    "endpoint": 1
  }
}
```

## Bridge Command Payload Format

The bridge accepts Matter commands in this structure:

```json
{
  "message_id": "1",
  "command": "device_command",
  "args": {
    "endpoint_id": 1,
    "cluster_id": 1292,
    "command_name": "LaunchApp",
    "payload": {},
    "timed_request_timeout_ms": 1000
  }
}
```

For Cluster 1292, always use `"cluster_id": 1292`. Payload keys are the command field names in lowerCamelCase. Octet-string fields are base64-encoded. `timed_request_timeout_ms` is required for timed commands and ignored otherwise.

# Command: `LaunchApp`

## Purpose

On receipt, the server must launch the application with optional data. The application is either - the specified application, if the Application Platform feature is supported; - otherwise the application corresponding to the endpoint. The endpoint must launch and bring to foreground the requisite application if the application is not already launched and in foreground. The Status attribute is updated to ActiveVisibleFocus on the Application Basic cluster of the Endpoint corresponding to the launched application.

## Command Identity

| Field | Value |
|---|---|
| Command ID | `0` |
| Command hex | `0x00` |
| Command name | `LaunchApp` |
| Direction | client → server |
| Conformance | `M` |
| Response | LauncherResponse |
| Access | (invoke: operate) |

## Payload Fields

| ID | Field | Payload key | Type | Conformance | Constraint | Meaning |
|---:|---|---|---|---|---|---|
| 0 | `Application` | `application` | ApplicationStruct | `AP` | desc | This field specifies the Application to launch. |
| 1 | `Data` | `data` | octstr | `O` | — | This field specifies optional app-specific data to be sent to the app. This format and meaning of this value is proprietary and outside the specification. |

## Bridge Command Example

```json
{
  "message_id": "1",
  "command": "device_command",
  "args": {
    "endpoint_id": 1,
    "cluster_id": 1292,
    "command_name": "LaunchApp",
    "payload": {
      "application": {
        "catalogVendorID": 1,
        "applicationID": "example"
      },
      "data": "AQID"
    }
  }
}
```

The device answers with `LauncherResponse` (see below).

# Command: `HideApp`

## Purpose

On receipt, the server must hide the application. The application is either - the specified application, if the Application Platform feature is supported; - otherwise the application corresponding to the endpoint. The endpoint may decide to stop the application based on manufacturer specific behavior or resource constraints if any. The Status attribute is updated to ActiveHidden or Stopped, depending on the action taken, on the Application Basic cluster of the Endpoint corresponding to the application on which the action was taken.
