# Matter Cluster 1030 — Occupancy Sensing Cluster

<Callout type="info">
Matter Cluster <code>1030</code>, also written as <code>0x0406</code>, is the <strong>Occupancy Sensing Cluster</strong>.
The server cluster provides an interface to occupancy sensing functionality based on one or more sensing modalities, including configuration and provision of notifications of occupancy status.
</Callout>

## Cluster 1030 Features

The `FeatureMap` attribute (`1/1030/65532`) is a bitmap. Each bit set means the device implements that feature and the attributes and commands that depend on it.

| Bit | Code | Feature | Conformance | Meaning |
|---:|---|---|---|---|
| 0 | `OTHER` | Other | `O` | Supports sensing using a modality not listed in the other bits |
| 1 | `PIR` | PassiveInfrared | `O` | Supports sensing using PIR (Passive InfraRed) |
| 2 | `US` | Ultrasonic | `O` | Supports sensing using UltraSound |
| 3 | `PHY` | PhysicalContact | `O` | Supports sensing using a physical contact |
| 4 | `AIR` | ActiveInfrared | `O` | Supports sensing using Active InfraRed measurement (e.g. time-of-flight or transflective/reflective IR sensing) |
| 5 | `RAD` | Radar | `O` | Supports sensing using radar waves (microwave) |
| 6 | `RFS` | RFSensing | `O` | Supports sensing using analysis of radio signals, e.g.: RSSI, CSI and/or any other metric from the signal |
| 7 | `VIS` | Vision | `O` | Supports sensing based on analyzing images |
| 9 | `OCCEVENT` | OccupancyEvent | `[ClusterRevision >= 7]` | Supports generating OccupancyChanged events |

Example: `FeatureMap` = `0` means no optional feature is enabled; `767` means every feature listed above is enabled.

## Attribute `0` / `0x0000` — `Occupancy`

Path example:

```text
1/1030/0
```

Indicates the sensed (processed) status of occupancy. For compatibility reasons this is expressed as a bitmap where the status is indicated in bit 0: a value of 1 means occupied, and 0 means unoccupied, with the other bits set to 0; this can be considered equivalent to a boolean.

| Constraint | 0 to 1 |

## Attribute `3` / `0x0003` — `HoldTime`

Path example:

```text
1/1030/3
```

This attribute specifies the time delay, in seconds, before the sensor changes to its unoccupied state after the last detection of occupancy in the sensed area. This is equivalent to the legacy &#42;OccupiedToUnoccupiedDelay attributes. Low values of HoldTime should be avoided since they could lead to many reporting messages. A value 0 for HoldTime must NOT be used.

| Property | Value |
|---|---|
| Type | uint16 |
| Conformance | `O` |
| Access | R/W (read: view, write: manage) |
| Qualities | persisted |
| Constraint | HoldTimeLimits to HoldTimeLimits |

Example:

```json
{
  "1/1030/3": 0
}
```

# SmartphoneKey Notes

- `Occupancy` (attribute `0`) is a bitmap; bit 0 set = occupied. Aqara FP400 presence sensors additionally expose vendor clusters that are not covered here.
- Shadow paths follow `endpoint/1030/attribute`; attribute values that the device reports as unreadable are written as `n/a`.
- Attribute IDs, command IDs and enum values on this page come from the CSA Matter 1.6.1 data model; descriptions are condensed from the specification text.
