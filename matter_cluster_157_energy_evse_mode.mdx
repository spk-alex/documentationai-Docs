# Matter Cluster 157 — Energy EVSE Mode Cluster

<Callout type="info">
Matter Cluster <code>157</code>, also written as <code>0x009D</code>, is the <strong>Energy EVSE Mode Cluster</strong>.
This cluster is derived from the Mode Base cluster and defines additional mode tags and namespaced enumerated values for EVSE devices.
</Callout>

<Callout type="info">
This cluster is <strong>derived from the Mode Base cluster</strong>: it inherits the base attributes, commands and data types listed below and adds the cluster-specific values. Where the base definition applies, the base text is used.
</Callout>

## Cluster 157 Features

The `FeatureMap` attribute (`1/157/65532`) is a bitmap. Each bit set means the device implements that feature and the attributes and commands that depend on it.

| Bit | Code | Feature | Conformance | Meaning |
|---:|---|---|---|---|
| 0 | `DEPONOFF` | OnOff | `X` | Dependency with the OnOff cluster |

Example: `FeatureMap` = `0` means no optional feature is enabled; `1` means every feature listed above is enabled.

# Attribute Details

## Attribute `0` / `0x0000` — `SupportedModes`

Path example:

```text
1/157/0
```

At least one entry in the SupportedModes attribute includes the Manual mode tag in the ModeTags field list. Modes with entries in the SupportedModes attribute which contain multiple mode tags permitting charging or discharging under different conditions must permit the charging or discharging to occur if any of the conditions are satisfied. Modes must NOT have both the Manual tag and the TimeOfUse or SolarCharging tags defined in the SupportedModes attribute.

## Bridge Command Payload Format

The bridge accepts Matter commands in this structure:

```json
{
  "message_id": "1",
  "command": "device_command",
  "args": {
    "endpoint_id": 1,
    "cluster_id": 157,
    "command_name": "ChangeToMode",
    "payload": {},
    "timed_request_timeout_ms": 1000
  }
}
```

For Cluster 157, always use `"cluster_id": 157`. Payload keys are the command field names in lowerCamelCase. Octet-string fields are base64-encoded. `timed_request_timeout_ms` is required for timed commands and ignored otherwise.
