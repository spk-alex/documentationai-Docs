# Matter Cluster 1106 — Thread Border Router Management Cluster

<Callout type="info">
Matter Cluster <code>1106</code>, also written as <code>0x0452</code>, is the <strong>Thread Border Router Management Cluster</strong>.
This cluster provides an interface for managing a Thread Border Router and the Thread network that it belongs to. Privileged nodes within the same fabric as a Thread Border Router can use these interfaces to request and set credentials information to the Thread network.
</Callout>

## Cluster 1106 Features

The `FeatureMap` attribute (`1/1106/65532`) is a bitmap. Each bit set means the device implements that feature and the attributes and commands that depend on it.

| Bit | Code | Feature | Conformance | Meaning |
|---:|---|---|---|---|
| 0 | `PC` | PANChange | `O` | The ability to change PAN configuration with pending dataset setting request. |

Example: `FeatureMap` = `0` means no optional feature is enabled; `1` means every feature listed above is enabled.

# Attribute Details

## Attribute `0` / `0x0000` — `BorderRouterName`

Path example:

```text

```

Indicates a user-friendly name identifying the device model or product of the Border Router in MeshCOP (DNS-SD service name) as defined in the Thread specification, and has the following recommended format: &lt;VendorName&gt; &lt;ProductName&gt;.&#95;meshcop.&#95;udp. ## Bridge Command Payload Format

The bridge accepts Matter commands in this structure:

```json
{
  "message_id": "1",
  "command": "device_command",
  "args": {
    "endpoint_id": 1,
    "cluster_id": 1106,
    "command_name": "GetActiveDatasetRequest",
    "payload": {},
    "timed_request_timeout_ms": 1000
  }
}
```

For Cluster 1106, always use `"cluster_id": 1106`. Payload keys are the command field names in lowerCamelCase. Octet-string fields are base64-encoded. `timed_request_timeout_ms` is required for timed commands and ignored otherwise.

# Command: `GetActiveDatasetRequest`

## Purpose

This command is used to request the active operational dataset of the Thread network to which the border router is connected. If the command is not executed via a CASE session, the command must fail with a status code of UNSUPPORTED_ACCESS. If an internal error occurs, then this command must fail with a FAILURE status code sent back to the initiator. Otherwise, this must generate a DatasetResponse command.

## Command Identity

| Field | Value |

| Command ID | `0` |

| Command name | `GetActiveDatasetRequest` |
| Direction | client → server |

## Payload Fields

# Command: `SetPendingDatasetRequest`

## Purpose

This command is used to set or update the pending Dataset of the Thread network to which the Border Router is connected, if the Border Router supports PAN Change.
