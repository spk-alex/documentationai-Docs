# Matter Cluster 97 — RVC Operational State Cluster

<Callout type="info">
Matter Cluster <code>97</code>, also written as <code>0x0061</code>, is the <strong>RVC Operational State Cluster</strong>.
This cluster is derived from the Operational State cluster and provides an interface for monitoring the operational state of a robotic vacuum cleaner.
</Callout>

<Callout type="info">
This cluster is <strong>derived from the Operational State cluster</strong>: it inherits the base attributes, commands and data types listed below and adds the cluster-specific values. Where the base definition applies, the base text is used.
</Callout>

# Attribute Details

## Attribute `0` / `0x0000` — `PhaseList`

Path example:

```text
1/97/0
```

Indicates a list of names of different phases that the device can go through for the selected function or mode. The list may not be in sequence order. For example in a washing machine this could include items such as "pre-soak", "rinse", and "spin". These phases are manufacturer specific and may change when a different function or mode is selected.

```json

  "args": {
    "endpoint_id": 1,

    "command_name": "GoHome",
    "payload": {},
    "timed_request_timeout_ms": 1000
  }
}
```

For Cluster 97, always use `"cluster_id": 97`. Payload keys are the command field names in lowerCamelCase. Octet-string fields are base64-encoded. `timed_request_timeout_ms` is required for timed commands and ignored otherwise.

# Command: `GoHome`

## Purpose

On receipt of this command, the device must start seeking the charging dock, if possible in the current state of the device. If this command is received when already in the SeekingCharger state the device must respond with an OperationalCommandResponse command with an ErrorStateID of NoError but the command has no other effect. A device that receives this command in any state which does not allow seeking the charger, such as Charging or Docked, must respond with an OperationalCommandResponse command with an ErrorStateID of CommandInvalidInState and has no other effect.

## Command Identity

| Field | Value |
|---|---|
| Command ID | `128` |

## Event `0` — `OperationalError`

This event is generated when a reportable error condition is detected. A device that generates this event must also set the OperationalState attribute to Error, indicating an error condition. This event contains the following fields:

| ID | Field | Type | Conformance | Meaning |
|---:|---|---|---|---|
| 0 | `ErrorState` | ErrorStateStruct | `M` | — |

## Event `1` — `OperationCompletion`

This event should be generated when the overall operation ends, successfully or otherwise. For example, the completion of a cleaning operation in a Robot Vacuum Cleaner, or the completion of a wash cycle in a Washing Machine. It is highly recommended that appliances device types employing the Operational State cluster support this event, even if it is optional.

| ID | Field | Type | Conformance | Meaning |
|---:|---|---|---|---|
| 0 | `CompletionErrorCode` | enum8 | `M` | This field provides an indication of the state at the end of the operation. This field has a value from the ErrorStateEnum set. |
| 1 | `TotalOperationalTime` | elapsed-s (nullable) | `O` | The total operational time, in seconds, from when the operation was started via an initial Start command or autonomous/manual starting action, until the operation completed. This includes any time spent while paused. |
| 2 | `PausedTime` | elapsed-s (nullable) | `O` | The total time spent in the paused state, in seconds. There may be cases whereby the total paused time exceeds the maximum value that can be conveyed by this attribute, in such instances, this attribute is populated with null. |
