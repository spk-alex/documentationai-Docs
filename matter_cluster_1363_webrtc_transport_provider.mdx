# Matter Cluster 1363 — WebRTC Transport Provider Cluster

<Callout type="info">
Matter Cluster <code>1363</code>, also written as <code>0x0553</code>, is the <strong>WebRTC Transport Provider Cluster</strong>.
The WebRTC transport provider cluster provides a way for stream providers (e.g. Cameras) to stream or receive their data through WebRTC. Devices implementing this cluster must also implement Camera AV Stream Management Cluster on the same endpoint.
</Callout>

## Bridge Command Payload Format

The bridge accepts Matter commands in this structure:

```json
{
  "message_id": "1",
  "command": "device_command",
  "args": {
    "endpoint_id": 1,
    "cluster_id": 1363,
    "command_name": "SolicitOffer",
    "payload": {},
    "timed_request_timeout_ms": 1000
  }
}
```

For Cluster 1363, always use `"cluster_id": 1363`. Payload keys are the command field names in lowerCamelCase. Octet-string fields are base64-encoded. `timed_request_timeout_ms` is required for timed commands and ignored otherwise.

# Command: `SolicitOfferResponse`

## Purpose

This command is generated in response to a SolicitOffer command. This response contains information about the session and streams created and/or if a deferred offer will take place. Upon receipt, the client must create a new WebRTCSessionStruct populated with the values from this command, along with the accessing Peer Node ID and Local Fabric Index entries stored in the Secure Session Context as the PeerNodeID and FabricIndex values, and store it in the WebRTC Transport Requestor cluster's CurrentSessions attribute. The session establishment is considered failed unless a Offer command is received by the Requestor from the PeerEndpointID / FabricIndex within 30 seconds.

| Field | Value |
|---|---|

| Direction | server → client (response) |

# Command: `ProvideAnswer`

## Purpose

This command is initiated from a Node in response to an Offer that was previously received from a remote peer. It has the following data fields: This command must respond with a response status of NOT_FOUND if the WebRTCSessionID does not match an entry in CurrentSessions, or if the matching entry's associated fabric and PeerNodeID do not match the accessing fabric and the Peer Node ID entry stored in the Secure Session Context of the session this command was received on.
