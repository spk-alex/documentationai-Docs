# Matter Cluster 30 — Binding Cluster

<Callout type="info">
Matter Cluster <code>30</code>, also written as <code>0x001E</code>, is the <strong>Binding Cluster</strong>.
This scope of this document is the Binding cluster as part of the Cluster Library. The Binding cluster is meant to replace the support from the Zigbee Device Object (ZDO) for supporting the binding table. A binding represents a persistent relationship between an endpoint and one or more other local or remote endpoints.
</Callout>

## Cluster 30 Attributes

Cluster 30 defines **1 attribute** plus the global attributes. Conformance: `M` mandatory, `O` optional, a feature code means "mandatory when that feature is present", square brackets mean "optional when …".

| ID | Hex | Attribute | Type | Conformance | Access | Qualities | Default |
|---:|---|---|---|---|---|---|---|
| 0 | `0x0000` | `Binding` | list of TargetStruct | `M` | R/W (read: view, write: manage, fabric-scoped) | persisted | `empty` |

# Attribute Details

## Attribute `0` / `0x0000` — `Binding`

Path example:

```text
0/30/0
```

Each entry represents a binding.

| Property | Value |
|---|---|
| Type | list of TargetStruct |
| Conformance | `M` |
| Access | R/W (read: view, write: manage, fabric-scoped) |
| Qualities | persisted |
| Constraint | desc |
| Default | `empty` |

Each entry is a `TargetStruct` (see Data Types).

Example:

```json
{
  "0/30/0": []
}
```

# Cluster 30 Commands

Cluster 30 defines **no commands**. It is read (and, for writable attributes, written) through attribute access only.

# Cluster 30 Events

Cluster 30 defines **no events**.

# SmartphoneKey Notes

- Shadow paths follow `endpoint/30/attribute`; attribute values that the device reports as unreadable are written as `n/a`.
