# Matter Cluster 1364 — WebRTC Transport Requestor Cluster

<Callout type="info">
Matter Cluster <code>1364</code>, also written as <code>0x0554</code>, is the <strong>WebRTC Transport Requestor Cluster</strong>.
The WebRTC transport requestor cluster provides a way for stream consumers (e.g. Matter Stream Viewer) to establish a WebRTC connection with a stream provider that implements the WebRTC Transport Provider Cluster.
</Callout>

## Bridge Command Payload Format

The bridge accepts Matter commands in this structure:

```json
{
  "message_id": "1",
  "command": "device_command",
  "args": {
    "endpoint_id": 1,
    "cluster_id": 1364,
    "command_name": "Offer",
    "payload": {},
    "timed_request_timeout_ms": 1000
  }
}
```

For Cluster 1364, always use `"cluster_id": 1364`. Payload keys are the command field names in lowerCamelCase. Octet-string fields are base64-encoded. `timed_request_timeout_ms` is required for timed commands and ignored otherwise.

# Command: `Offer`

## Purpose

This command provides the stream requestor with WebRTC session details. It is sent following the receipt of a SolicitOffer command or a re-offer initiated by the Provider. This command must respond with a response status of NOT_FOUND if the WebRTCSessionID does not match an entry in CurrentSessions, or if the matching entry's associated fabric and PeerNodeID do not match the accessing fabric and the Peer Node ID entry stored in the Secure Session Context of the session this command was received on.

## Purpose

This command provides the stream requestor with the WebRTC session details (i.e. Session ID and SDP answer), It is the next command in the Offer/Answer flow to the ProvideOffer command.
