# Matter Cluster 1284 — Channel Cluster

<Callout type="info">
Matter Cluster <code>1284</code>, also written as <code>0x0504</code>, is the <strong>Channel Cluster</strong>.
This cluster provides an interface for controlling the current Channel on a device or endpoint. This cluster server would be supported on Video Player devices or endpoints that allow Channel control such as a Content App. This cluster provides a list of available channels and provides commands for absolute and relative channel changes.
</Callout>

## Cluster 1284 Features

The `FeatureMap` attribute (`1/1284/65532`) is a bitmap. Each bit set means the device implements that feature and the attributes and commands that depend on it.

| Bit | Code | Feature | Conformance | Meaning |
|---:|---|---|---|---|
| 0 | `CL` | ChannelList | `O` | Provides list of available channels |
| 1 | `LI` | LineupInfo | `O` | Provides lineup info, which is a reference to an external source of lineup information |
| 2 | `EG` | ElectronicGuide | `O` | Provides electronic program guide information |
| 3 | `RP` | RecordProgram | `O` | Provides ability to record program |

Example: `FeatureMap` = `0` means no optional feature is enabled; `15` means every feature listed above is enabled.

The bridge accepts Matter commands in this structure:

```json
{
  "message_id": "1",
  "command": "device_command",
  "args": {
    "endpoint_id": 1,
    "cluster_id": 1284,
    "command_name": "ChangeChannel",
    "payload": {},
    "timed_request_timeout_ms": 1000
  }
}
```

For Cluster 1284, always use `"cluster_id": 1284`. Payload keys are the command field names in lowerCamelCase. Octet-string fields are base64-encoded. `timed_request_timeout_ms` is required for timed commands and ignored otherwise.

# Command: `ChangeChannel`

## Purpose

Change the channel to the channel case-insensitive exact matching the value passed as an argument. The match priority order is: Identifier, AffiliateCallSign, CallSign, Name, Number. In the match string, the Channel number should be presented in the Major.Minor format, such as 13.1. Upon receipt, this must generate a ChangeChannelResponse command.

# Command: `SkipChannel`

## Purpose

This command provides channel up and channel down functionality, but allows channel index jumps of size Count. Jumps are relative to the available list of channels. For example, when the current channel is 100.0 and the list of available channels is &#91;100.0, 200.0, 201.0, 305.1&#93;, a SkipChannel command with jump value of 2 must change the channel to 201.0. When the value of the increase or decrease is larger than the number of channels remaining in the given direction, then the behavior is to return to the beginning (or end) of the channel list and continue.
