# Matter クラスター ドキュメント

## Matter とは

Matter は、スマートデバイスの相互運用性を実現するための標準規格です。ベンダーごとにまったく異なるデバイスデータモデルを考案するのではなく、Matter が共通の構造を定義することで、コントローラー、アプリ、ハブ、クラウドシステムがデバイスを予測可能な形で理解できるようになります。

最も重要な構成要素は次のとおりです。

- **ノード (Node)**: ネットワーク上の物理デバイス全体です。
- **エンドポイント (Endpoint)**: デバイスの機能上の一部分です。1 つの物理製品が複数のエンドポイントを公開することがあります。
- **クラスター (Cluster)**: 関連する機能やプロパティをまとめたグループです。クラスターは、*Door Lock*、*Battery*、*Temperature Measurement* のようなトピック領域だと考えてください。
- **属性 (Attribute)**: クラスター内の特定の 1 つの値です。たとえば `LockState` や `BatVoltage` があります。
- **コマンド (Command)**: クラスターに送信できるアクションです。たとえばロックデバイスの施錠/解錠があります。

## 表の読み方

- **エンドポイント** は、その行がデバイスのどの機能部分に属するかを示します。
- **クラスター** は、人が読めるクラスター名と、その後ろの括弧内に数値 ID を示します。例: `Basic Information (40)`。
- **属性** は、クラスターが公開する正確なプロパティです。
- **パス** は `endpoint/cluster/attribute` の形式で、インラインコードとして表示されます。

各属性の詳しい意味、値のセマンティクス、および例は、各表の下にある展開可能なカードに記載しています。

## 初めての方への重要な注意

クラスターはデバイスタイプと同じものではありません。

たとえば、**Boolean State** クラスターが返すのは `true/false` の値だけです。この値の意味は、エンドポイントのデバイスタイプによって大きく異なります。

- 接触センサーの場合は、**開/閉** を意味することがあります
- 漏水センサーの場合は、**漏水あり/漏水なし** を意味することがあります

そのため、Matter のデータは常に次の両方を用いて解釈する必要があります。

1. クラスターと属性
2. エンドポイントの役割 / デバイスタイプのコンテキスト

## フィールドの詳細

**VendorName** — 人が読めるベンダー名です。例: `"SmartphoneKey Systems Inc"`。文字列値です。列挙値ではありません。デバイスが報告するベンダーの表示名であるため、メーカーごとに異なるテキストが返されます。

**ProductName** — 人が読める製品名です。例: `"SmartphoneKey Reader"`。文字列値です。ノードが公開する製品/モデルの表示名であり、デバイスタイプの列挙値ではありません。

**HardwareVersionString** — ハードウェアバージョンの文字列です。例: `"release"`。文字列値です。通常は、人が読めるハードウェアリビジョン、基板リビジョン、またはリリースラベルです。ベンダー定義のテキストとして扱ってください。

**SoftwareVersionString** — ソフトウェア/ファームウェアバージョンの文字列です。例: `"1.26.1+1"`。文字列値です。通常はファームウェア/ソフトウェアのバージョンです。ベンダーがセマンティックバージョン、ビルドメタデータ、独自のラベルを含めることがあるため、テキストとして扱ってください。

**ManufacturingDate/DateCode** — デバイスが提供する製造日または日付コードです。例: `"20250903"`。文字列/日付コードの値です。形式はベンダーが決めます。このエクスポートでは `YYYYMMDD` のように見えますが、すべてのデバイスが同じ形式を使うとは想定しないでください。

**SerialNumber** — シリアル番号の文字列です。例: `"11064672519639222187"`。文字列値です。物理的なシリアル番号です。数値のように見えることがありますが、先頭のゼロや書式が失われないようにテキストとして保存してください。

**VendorID** — ベンダー識別子です。例: `4619`。Matter/CSA のベンダー ID 割り当てプロセスで付与される数値のベンダー識別子です。数値として保存しますが、エンジニアリングログでは 16 進数表示も役立ちます。

**ProductURL** — 製品 URL です (実装されている場合)。例: `""`。実装されている場合は URL の文字列値です。空文字列は、デバイスが製品/サポートの URL を提供していないことを意味します。

**UpTime** — 現在の稼働時間です。例: `588758`。秒単位の数値です。この例は、デバイスが最後の起動から 588,758 秒間稼働していることを意味します。値が急に小さくなった場合は、通常、ノードが最近再起動したことを示します。

**TotalOperationalHours** — 総稼働時間です。例: `163`。時間単位の数値です。この例は、デバイスが合計 163 時間の稼働を報告していることを意味します。デバイスが値を永続化している場合、この値は累積されます。

**BootReason** — 直近の起動の理由です。例: `6`。列挙値です。Matter での一般的な意味は `0 = Unspecified`、`1 = PowerOnReboot`、`2 = BrownOutReset`、`3 = SoftwareWatchdogReset`、`4 = HardwareWatchdogReset`、`5 = SoftwareUpdateCompleted`、`6 = SoftwareReset` です。この例の `6` は、ソフトウェアによるリセット/再起動を意味します。

<Callout type="warning">
Thread Network Diagnostics (クラスター <code>53</code>) は、現在のブリッジではデバイスの状態シャドウから除外されています。そのため、上記の <code>0/53/&#42;</code> の行は、ブリッジがノードから読み取る内容を表すものであり、シャドウ内に存在するキーではありません。<a href="/matter_cluster_53_thread_network_diagnostics">Cluster 53 — Thread Network Diagnostics</a> を参照してください。Wi-Fi 診断 (<code>0/54/&#42;</code>) はシャドウに反映されます。<a href="/matter_cluster_54_wifi_network_diagnostics">Cluster 54 — Wi-Fi Network Diagnostics</a> を参照してください。
</Callout>

**NeighborTable** — ネイバーテーブルのエントリです。例: `[{"averageRssi": -25, ...}]`、または簡略化して `[-25]`。テーブル/リストの値です。各エントリは Thread のネイバー 1 つを表します。RSSI 値は通常、負の dBm です。0 に近いほど強く、`-25` 前後は非常に強い、`-50` は良好、`-70` は弱い信号です。

**RoutingRole** — 現在の Thread ルーティングロールです。例: `6`。Thread のロールを表す列挙値です。一般的な値は、実装や仕様のバージョンに応じて、無効、デタッチ、チャイルド/エンドデバイス、ルーター、リーダー、ボーダールーター対応ロールといった状態を表します。主に診断用であり、ビジネス上の状態としては使用しないでください。

**NetworkName** — Thread ネットワーク名です。例: `"OpenThread-952e"`。文字列値です。デバイスが正しいネットワークに参加していれば、想定している Thread メッシュの名前と一致するはずです。

**RSSI** — 受信信号強度インジケーターです。例: `nan`。報告される場合は dBm 単位の数値です。Wi-Fi の RSSI は通常負の値で、0 に近いほど強い信号です。`nan`、null、または値がない場合は、通常、Wi-Fi が使用されていないか、デバイスが値を報告していないことを意味します。

**IdleModeDuration** — ICD 動作におけるアイドルモードの継続時間です。例: `300`。秒単位の数値です。ICD デバイスでは、デバイスがスリープしたり、すぐには到達できなくなったりする可能性があるアイドルモードの間隔を表します。

**ActiveModeDuration** — ICD 動作におけるアクティブモードの継続時間です。例: `300`。Matter の ICD 定義ではミリ秒単位の数値です。ウェイク/アクティブ動作の後、アイドル動作に戻るまでにデバイスがアクティブモードにとどまる時間を表します。

**ActiveModeThreshold** — アクティブモードに入るためのしきい値です。例: `300`。ミリ秒単位の数値のしきい値です。ICD 動作において、アクティブモードのタイミングや応答性を決めるために使用されます。値が大きいほど、通常はデバイスが応答可能な時間が長くなりますが、バッテリーに影響することがあります。

**UserActiveModeTriggerHint** — アクティブモードを起動する方法を示すヒントです。例: `4381`。ビットマップ/ビットマスクの値です。各ビットは、デバイスをウェイクまたはアクティブ化できるユーザー操作の候補を示します。単一の数値としてではなく、フラグとしてデコードしてください。人が読める手順については `UserActiveModeTriggerInstruction` と組み合わせて使用します。

**UserActiveModeTriggerInstruction** — ユーザーがアクティブモードを起動するための手順テキストです。例: `"Restart the application"`。文字列値です。ユーザーがアクティブモードを起動する方法を説明する、人が読める手順です。必要に応じてそのまま表示できるテキストです。

| クラスター | 属性 | パス |
| --- | --- | --- |
| Occupancy Sensing (1030) | Occupancy | `1/1030/0` |

**Occupancy** — 現在の在室/人感の状態です。例: `0`。ビットマップ値です。ビット 0 は在室/人の存在を検知したことを示します。`0` は在室を検知していないこと、`1` は在室していることを意味します。今後追加されるビットが、ほかの検知モードを表す可能性があります。

### 煙検知器

これらの行は、エンドポイントが現在、自身で煙を検知しているか、または連動する別の煙検知器から煙アラームの状態を受信しているかを示します。

| クラスター | 属性 | パス |
|---|---|---|
| Smoke CO Alarm (92) | SmokeState | `1/92/0` |
| Smoke CO Alarm (92) | InterconnectSmokeAlarm | `1/92/7` |

**SmokeState** — この検知器自身のローカルな煙の状態です。

```text
0 = Normal / no local smoke detected
1 = Warning / local smoke warning
2 = Critical / local smoke alarm
```

**InterconnectSmokeAlarm** — 同じ連動アラームグループ内の別の検知器から受信した煙アラームの状態です。

```text
0 = Normal / no interconnected smoke alarm
1 = Warning / another detector reports smoke warning
2 = Critical / another detector reports critical smoke alarm
```

#### 違い

`SmokeState` は、この検知器自身が煙を検知していることを意味します。

`InterconnectSmokeAlarm` は、連動している別の検知器が煙を報告しており、この検知器がそのアラーム状態を公開していることを意味します。

例:

```json
{
  "1/92/0": 0,
  "1/92/7": 2
}
```

この例は、この検知器自身は煙を検知していないものの、連動している別の検知器が重大な煙アラームを報告していることを意味します。

#### 解釈

| `1/92/0` SmokeState | `1/92/7` InterconnectSmokeAlarm | ローカルの煙 | 連動先の煙 | 最終的な状態 |
|---|---|---|---|---|
| `0` | `0` | なし | なし | 正常 / 煙の検知なし |
| `1` | `0` | 警告 | なし | ローカルの煙警告 |
| `2` | `0` | 重大 | なし | ローカルの重大な煙アラーム |
| `0` | `1` | なし | 警告 | 別の検知器が煙警告を報告 |
| `0` | `2` | なし | 重大 | 別の検知器が重大な煙アラームを報告 |
| `1` | `1` | 警告 | 警告 | ローカルおよび連動先の煙警告 |
| `1` | `2` | 警告 | 重大 | 連動先の重大な煙アラームが作動中 |
| `2` | `1` | 重大 | 警告 | ローカルの重大な煙アラームが作動中 |
| `2` | `2` | 重大 | 重大 | 重大な煙アラームが作動中 |

## サポートされるコマンド

このセクションでは、コマンドの対応状況について説明します。これらのフィールドは、デバイスがアクションとして受け付けられる内容を表します。Matter では、コマンドのサポートは通常、グローバル属性 `AcceptedCommandList` から検出します。パスの形式は `endpoint/cluster/65529` です。

このセクションは **デバイス情報データ** とは区別して使用してください。

- **デバイス情報データ** = デバイスが報告する属性です。例: `0/40/1`、`1/257/0`、`1/47/12`。
- **サポートされるコマンド** = デバイス/クラスターが受け付けるアクションです。例: `LockDoor`、`UnlockDoor`、`GetUser`、または一般的なコミッショニングコマンド。

### Matter のコマンド対応状況フィールド

Matter は、クラスターのグローバル属性を通じてコマンドの対応状況を公開します。`endpoint/cluster/attribute` 形式で最も重要なコマンド対応状況のパスは次のとおりです。

| 属性 ID | 16 進数 | 属性名 | 意味 |
| --- | --- | --- | --- |
| 65529 | `0xFFF9` | AcceptedCommandList | このクラスターサーバーが受け付けるコマンド ID のリスト。ブリッジ/API がコマンドを送信できるかどうかの判断に使用します。 |
| 65528 | `0xFFF8` | GeneratedCommandList | このクラスターが応答/イベントとして生成し得るコマンド ID のリスト。コマンド応答の処理に役立ちますが、対応状況を確認する主な手段ではありません。 |

パスの例: `0/49/65529` は、エンドポイント `0`、クラスター `49`、属性 `65529` を意味します。これにより、Network Commissioning クラスターがエンドポイント `0` で受け付けるコマンドがわかります。

### すべての Matter デバイスタイプに共通するエンドポイント 0 のコマンド

エンドポイント `0` は、ルート/システムエンドポイントです。これらのコマンドはロック固有のものではありません。Matter に共通する、システム、コミッショニング、診断、セキュリティ、ファブリック管理の機能です。どのデバイスタイプでも、対応状況に応じてこれらのクラスターの一部を公開することがあります。

| パス | クラスター ID | クラスター名 | 受け付けるコマンド ID | デコードしたコマンド | 意味 |

### Door Lock クラスターでサポートされるコマンド

Door Lock クラスターには、ロックの操作、ユーザー/PIN/RFID の管理、スケジュール、クレデンシャル、ログ、Aliro リーダーの設定のためのコマンドセットがあります。重要: 実際のロックは、これらのコマンドの一部しかサポートしていないことがあります。特定のデバイスが何をサポートしているかを知るには、ロックのエンドポイントでクラスター `257` の標準グローバル属性 `AcceptedCommandList` を読み取ってください。`endpoint/cluster/attribute` 形式を使用する場合、たとえばパスは `1/257/65529` です。

python-matter-server / ブリッジを使用する場合、コマンドは通常、ロックのエンドポイント (通常はエンドポイント `1`) のクラスター `257` に送信します。AWS IoT のペイロードでは、ブリッジが `device_uuid -> node_id` を解決したうえで、`node_id`、`endpoint_id`、クラスターのコマンド名、コマンド固有の引数を指定してコマンドを送信する必要があります。

#### Door Lock コマンドのサポート確認

Door Lock コマンドのサポートは、上記のエンドポイント `0` の一般的なシステムコマンドとは別のものです。すべての Matter ロックが上記のコマンドをすべてサポートしているとは想定しないでください。実際にサポートを確認する方法は次のとおりです。

| パス | 属性 | わかること | 例 / 値の詳細 |
| --- | --- | --- | --- |
| `1/257/65529` | AcceptedCommandList | この特定のロックがエンドポイント `1`、クラスター `257` で受け付けるコマンド。 | 例: `[0, 1, 26, 27, 29, 34, 36, 38]` は、このロックが `LockDoor`、`UnlockDoor`、`SetUser`、`GetUser`、`ClearUser`、`SetCredential`、`GetCredentialStatus`、`ClearCredential` をサポートしていることを意味します。このリストを使用して、公開する API のボタン/機能を決定します。 |
| `1/257/65528` | GeneratedCommandList | 実装に応じて、このクラスターがコマンドに対して生成する応答/イベント。 | コマンド/応答の処理に役立ちますが、コマンドを送信できるかどうかを判断する主な手段は `AcceptedCommandList` です。 |

## Matter デバイスタイプのマッピング

### 信頼できる情報源

Matter デバイスタイプは、Matter の Descriptor クラスターから読み取ります。

```text
<endpoint>/29/0
```

次の意味です。

```text
29 = Descriptor cluster
0  = DeviceTypeList attribute
```

`python-matter-server` は値を 10 進数形式で返します。

```json
"1/29/0": [
  {
    "0": 21,
    "1": 1
  }
]
```

意味:

```text
"0" = Matter Device Type ID
"1" = Device Type Revision
```

Matter SDK の公式データモデルでは、Matter 1.5 のデバイスタイプ ID マップが `connectedhomeip/data_model/1.5/device_types/device_type_ids.json` で公開されています。

出典:

- https://github.com/project-chip/connectedhomeip/blob/master/data_model/1.5/device_types/device_type_ids.json

### ブリッジのルール

#### `device_info` シャドウ

`device_info` シャドウには、Matter デバイスタイプの数値が実際の Matter パスの下に保存されます。

Contact Sensor の例:

```json
{
  "1/29/0": 21
}
```

次のカスタムフィールドを `device_info` に書き込まないでください。

```json
{
  "device_type": "contact_sensor"
}
```

#### 複合センサーのルール

物理デバイスによっては、複数のセンサーエンドポイントを公開するものがあります。

例:

```text
770 = Temperature Sensor
775 = Humidity Sensor
```

ブリッジはこれらを次のように統合します。

```text
temperature_humidity_sensor
```

この場合も、`device_info` シャドウには、選択された 1 つの数値の Matter パスだけが保存されます。例:

```json
{
  "1/29/0": 770
}
```

ただし、ブリッジの内部タイプと AWS IoT の Thing Type は次のようになります。

```text
temperature_humidity_sensor
```
