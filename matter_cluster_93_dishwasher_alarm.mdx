# Matter Cluster 93 — Dishwasher Alarm Cluster

<Callout type="info">
Matter Cluster <code>93</code>, also written as <code>0x005D</code>, is the <strong>Dishwasher Alarm Cluster</strong>.
This cluster is a derived cluster of the Alarm Base cluster and provides the alarm definition related to dishwasher devices.
</Callout>

<Callout type="info">
This cluster is <strong>derived from the Alarm Base cluster</strong>: it inherits the base attributes, commands and data types listed below and adds the cluster-specific values. Where the base definition applies, the base text is used.
</Callout>

## Bridge Command Payload Format

The bridge accepts Matter commands in this structure:

```json
{
  "message_id": "1",
  "command": "device_command",
  "args": {
    "endpoint_id": 1,
    "cluster_id": 93,
    "command_name": "Reset",
    "payload": {},
    "timed_request_timeout_ms": 1000
  }
}
```

For Cluster 93, always use `"cluster_id": 93`. Payload keys are the command field names in lowerCamelCase. Octet-string fields are base64-encoded. `timed_request_timeout_ms` is required for timed commands and ignored otherwise.

## Event `0` — `Notify`

This event is generated when one or more alarms change state.

| ID | Field | Type | Conformance | Meaning |
|---:|---|---|---|---|
| 0 | `Active` | AlarmBitmap | `M` | Indicates those alarms that have become active. |
| 1 | `Inactive` | AlarmBitmap | `M` | Indicates those alarms that have become inactive. |
| 2 | `State` | AlarmBitmap | `M` | This field is a copy of the new State attribute value that resulted in the event being generated. That is, this field has all the bits in Active set and must NOT have any of the bits in Inactive set. |
| 3 | `Mask` | AlarmBitmap | `M` | This field is a copy of the Mask attribute when this event was generated. |
