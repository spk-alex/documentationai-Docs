# Matter Cluster 69 — Boolean State Cluster

<Callout type="info">
Matter Cluster <code>69</code>, also written as <code>0x0045</code>, is the <strong>Boolean State Cluster</strong>.
This cluster provides an interface to a boolean state.
</Callout>

## Cluster 69 Features

The `FeatureMap` attribute (`1/69/65532`) is a bitmap. Each bit set means the device implements that feature and the attributes and commands that depend on it.

| Bit | Code | Feature | Conformance | Meaning |
|---:|---|---|---|---|
| 0 | `CHGEVENT` | ChangeEvent | `[ClusterRevision >= 3]` | Supports reporting change events |

Example: `FeatureMap` = `0` means no optional feature is enabled; `1` means every feature listed above is enabled.

# Attribute Details

## Attribute `0` / `0x0000` — `StateValue`

Path example:

```text
1/69/0
```

This represents a boolean state. The semantics of this boolean state are defined by the device type using this cluster. For example, in a Contact Sensor device type, FALSE=open or no contact, TRUE=closed or contact.

| Property | Value |
|---|---|
| Type | bool |
| Conformance | `M` |
| Access | R (read: view) |

Example:

```json
{
  "1/69/0": true
}
```

# Cluster 69 Commands

Cluster 69 defines **no commands**. It is read (and, for writable attributes, written) through attribute access only.

# SmartphoneKey Notes

- Boolean State is used by contact, leak and similar sensors. The meaning of `StateValue` depends on the endpoint device type: contact sensor `true` = closed; water leak detector `true` = leak detected.
- Shelly Flood leak sensors are Long Idle Time ICDs: live reads of `0/69/0` can time out; rely on reported (subscribed) values in the shadow.
- Shadow paths follow `endpoint/69/attribute`; attribute values that the device reports as unreadable are written as `n/a`.
- Attribute IDs, command IDs and enum values on this page come from the CSA Matter 1.6.1 data model; descriptions are condensed from the specification text.
