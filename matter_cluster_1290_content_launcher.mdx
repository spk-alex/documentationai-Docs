# Matter Cluster 1290 — Content Launcher Cluster

<Callout type="info">
Matter Cluster <code>1290</code>, also written as <code>0x050A</code>, is the <strong>Content Launcher Cluster</strong>.
This cluster provides an interface for launching content on a Video Player device such as a Streaming Media Player, Smart TV or Smart Screen. This cluster would be supported on a Video Player device or devices that can playback content, such as a Streaming Media Player, Smart TV or Smart Screen. This cluster supports playing back content referenced by URL.
</Callout>

## Cluster 1290 Features

The `FeatureMap` attribute (`1/1290/65532`) is a bitmap. Each bit set means the device implements that feature and the attributes and commands that depend on it.

| Bit | Code | Feature | Conformance | Meaning |
|---:|---|---|---|---|
| 0 | `CS` | ContentSearch | `O` | Device supports content search (non-app specific) |
| 1 | `UP` | URLPlayback | `O` | Device supports basic URL-based file playback |
| 2 | `AS` | AdvancedSeek | `O` | Enables clients to implement more advanced media seeking behavior in their user interface, such as for example a "seek bar" |
| 3 | `TT` | TextTracks | `O` | Device or app supports Text Tracks |
| 4 | `AT` | AudioTracks | `O` | Device or app supports Audio Tracks |

Example: `FeatureMap` = `0` means no optional feature is enabled; `31` means every feature listed above is enabled.

## Bridge Command Payload Format

The bridge accepts Matter commands in this structure:

```json
{
  "message_id": "1",
  "command": "device_command",
  "args": {
    "endpoint_id": 1,
    "cluster_id": 1290,
    "command_name": "LaunchContent",
    "payload": {},
    "timed_request_timeout_ms": 1000
  }
}
```

For Cluster 1290, always use `"cluster_id": 1290`. Payload keys are the command field names in lowerCamelCase. Octet-string fields are base64-encoded. `timed_request_timeout_ms` is required for timed commands and ignored otherwise.

# Command: `LaunchContent`

## Purpose

On receipt, this must launch the specified content with optional search criteria. This command returns a Launch Response.

## Command Identity

| Field | Value |
|---|---|
| Command ID | `0` |
| Command hex | `0x00` |
| Command name | `LaunchContent` |
| Direction | client → server |
| Conformance | `CS` |
| Response | LauncherResponse |
| Access | (invoke: operate) |

## Payload Fields

| ID | Field | Payload key | Type | Conformance | Constraint | Meaning |
|---:|---|---|---|---|---|---|
| 0 | `Search` | `search` | ContentSearchStruct | `M` | desc | Indicates the content to launch. |
| 1 | `AutoPlay` | `autoPlay` | bool | `M` | desc | Indicates whether to automatically start playing content, where: - TRUE means best match should start playing automatically. - FALSE means matches should be displayed on screen for user selection. |
| 2 | `Data` | `data` | string | `O` | — | This field, if present, indicates app-specific data. |
| 3 | `PlaybackPreferences` | `playbackPreferences` | PlaybackPreferencesStruct | `O` | — | This field, if present, indicates the user's preferred Text/AudioTracks and playbackPosition for the media, sent from the client to the server. |
| 4 | `UseCurrentContext` | `useCurrentContext` | bool | `O` | desc | This field, if present, indicates whether to consider the context of current ongoing activity on the receiver to fulfill the request. |

## Bridge Command Example

```json
{
  "message_id": "1",
  "command": "device_command",
  "args": {
    "endpoint_id": 1,
    "cluster_id": 1290,
    "command_name": "LaunchContent",
    "payload": {
      "search": {
        "parameterList": []
      },
      "autoPlay": true
    }
  }
}
```

The device answers with `LauncherResponse` (see below).
