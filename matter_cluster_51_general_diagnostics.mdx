# Matter Cluster 51 — General Diagnostics Cluster

<Callout type="info">
Matter Cluster <code>51</code>, also written as <code>0x0033</code>, is the <strong>General Diagnostics Cluster</strong>.
The General Diagnostics Cluster, along with other diagnostics clusters, provide a means to acquire standardized diagnostics metrics that may be used by a Node to assist a user or Administrator in diagnosing potential problems. The General Diagnostics Cluster attempts to centralize all metrics that are broadly relevant to the majority of Nodes.
</Callout>

Path example:

The RebootCount attribute indicates a best-effort count of the number of times the Node has rebooted. The RebootCount attribute should be incremented each time the Node reboots. The RebootCount attribute must NOT be incremented when a Node wakes from a low-power or sleep state. The RebootCount attribute only be reset to 0 upon a factory reset of the Node.

## Bridge Command Payload Format

The bridge accepts Matter commands in this structure:

```json
{
  "message_id": "1",
  "command": "device_command",
  "args": {
    "endpoint_id": 0,
    "cluster_id": 51,
    "command_name": "TestEventTrigger",
    "payload": {},
    "timed_request_timeout_ms": 1000
  }
}
```

For Cluster 51, always use `"cluster_id": 51`. Payload keys are the command field names in lowerCamelCase. Octet-string fields are base64-encoded. `timed_request_timeout_ms` is required for timed commands and ignored otherwise.

# Command: `TimeSnapshot`

## Purpose

This command may be used by a client to obtain a correlated view of both System Time, and, if currently synchronized and supported, "wall clock time" of the server. This can help clients establish time correlation between their concept of time and the server's concept of time. This is especially useful when processing event histories where some events only contain System Time. Upon command invocation, the server must respond with a TimeSnapshotResponse.

## Command Identity

| Direction | client → server |

# Command: `TimeSnapshotResponse`

## Purpose

This command is generated in response to a TimeSnapshot command. When generating this response, all fields is gathered as close together in time as possible, so that the time jitter between the values is minimized. If the Time Synchronization cluster is supported by the node, the PosixTimeMs field must NOT be null unless the UTCTime attribute in the Time Synchronization cluster is also null.
