# Matter Cluster 257 — Door Lock Cluster

<Callout type="info">
Matter Cluster <code>257</code>, also written as <code>0x0101</code>, is the <strong>Door Lock Cluster</strong>.
The door lock cluster provides an interface to a generic way to secure a door. The physical object that provides the locking functionality is abstracted from the cluster. The cluster has a small list of mandatory attributes and functions and a list of optional features.
</Callout>

# Attribute Details

## Attribute `0` / `0x0000` — `LockState`

Path example:

```text
1/257/0
```

This attribute may be null if the lock hardware does not currently know the status of the locking mechanism. For example, a lock may not know the LockState status after a power cycle until the first lock actuation is completed. The Not Fully Locked value is used by a lock to indicate that the state of the lock is somewhere between Locked and Unlocked so it is only partially secured. For example, a deadbolt could be partially extended and not in a dead latched state.

| Property | Value |

## Attribute `136` / `0x0088` — `NumberOfAliroEndpointKeysSupported`

Path example:

Indicates the maximum number of endpoint key credentials that can be stored on the lock. The credential indices used for these two credential types are independent of each other, similar to all other credential types. As long as NumberOfAliroEndpointKeysSupported is at least 2 a client could add a credential of type AliroEvictableEndpointKey at any index from 1 to NumberOfAliroEndpointKeysSupported and also add a credential of type AliroNonEvictableEndpointKey at the same index, and both credentials would exist on the server.

# SmartphoneKey Notes

- Door locks are the primary SmartphoneKey device class. `LockState` (`1/257/0`) drives the lock/unlock state shown in the app.
- `LockDoor` / `UnlockDoor` are timed commands: the bridge sends them with `timed_request_timeout_ms`. Yale locks enforce a 60 s lockout after repeated wrong PIN codes.
- `PINCode` in command payloads is sent as a base64-encoded octet string.
- User, credential and schedule management commands (`SetUser`, `SetCredential`, ...) require the lock to report the `USR` / `PIN` features in `FeatureMap`.
- Shadow paths follow `endpoint/257/attribute`; attribute values that the device reports as unreadable are written as `n/a`.
- Attribute IDs, command IDs and enum values on this page come from the CSA Matter 1.6.1 data model; descriptions are condensed from the specification text.
