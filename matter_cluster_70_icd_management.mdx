# Matter Cluster 70 — ICD Management Cluster

<Callout type="info">
Matter Cluster <code>70</code>, also written as <code>0x0046</code>, is the <strong>ICD Management Cluster</strong>.
ICD Management Cluster enables configuration of the ICD's behavior and ensuring that listed clients can be notified when an intermittently connected device, ICD, is available for communication. The cluster implements the requirements of the Check-In Protocol that enables the ICD Check-In use case.
</Callout>

## Cluster 70 Features

The `FeatureMap` attribute (`0/70/65532`) is a bitmap. Each bit set means the device implements that feature and the attributes and commands that depend on it.

| Bit | Code | Feature | Conformance | Meaning |
|---:|---|---|---|---|
| 0 | `CIP` | CheckInProtocolSupport | `LITS, O` | Device supports attributes and commands for the Check-In Protocol support |
| 1 | `UAT` | UserActiveModeTrigger | `LITS, O` | Device supports the user active mode trigger feature |
| 2 | `LITS` | LongIdleTimeSupport | `O` | Device supports operating as a Long Idle Time ICD |
| 3 | `DSLS` | DynamicSitLitSupport | `[LITS]` | Device supports dynamic switching from SIT to LIT operating modes |

Example: `FeatureMap` = `0` means no optional feature is enabled; `15` means every feature listed above is enabled.

## Bridge Command Payload Format

The bridge accepts Matter commands in this structure:

```json
{
  "message_id": "1",
  "command": "device_command",
  "args": {
    "endpoint_id": 0,
    "cluster_id": 70,
    "command_name": "RegisterClient",
    "payload": {},
    "timed_request_timeout_ms": 1000
  }
}
```

For Cluster 70, always use `"cluster_id": 70`. Payload keys are the command field names in lowerCamelCase. Octet-string fields are base64-encoded. `timed_request_timeout_ms` is required for timed commands and ignored otherwise.

# Command: `StayActiveRequest`

## Purpose

This command allows a client to request that the server stays in active mode for at least a given time duration (in milliseconds) from when this command is received. This StayActiveDuration may be longer than the ActiveModeThreshold value and would, typically, be used by the client to request the server to stay active and responsive for this period to allow a sequence of message exchanges during that period. The client may slightly overestimate the duration it wants the ICD to be active for, in order to account for network delays.

# SmartphoneKey Notes

- Sleepy devices (locks, sensors) are ICDs: expect `0/70/*` on them. Long Idle Time (LIT) devices only wake on their own schedule; live attribute reads time out by design.
- Shadow paths follow `endpoint/70/attribute`; attribute values that the device reports as unreadable are written as `n/a`.
- Attribute IDs, command IDs and enum values on this page come from the CSA Matter 1.6.1 data model; descriptions are condensed from the specification text.
