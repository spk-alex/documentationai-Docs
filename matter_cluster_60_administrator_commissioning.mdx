# Matter Cluster 60 — Administrator Commissioning Cluster

<Callout type="info">
Matter Cluster <code>60</code>, also written as <code>0x003C</code>, is the <strong>Administrator Commissioning Cluster</strong>.
This cluster is used to trigger a Node to allow a new Administrator to commission it. It defines Attributes, Commands and Responses needed for this purpose. For the management of Operational Credentials and Trusted Root Certificates, the Operational Credentials cluster is used.
</Callout>

# Attribute Details

## Attribute `0` / `0x0000` — `WindowStatus`

Path example:

```text
0/60/0
```

Indicates whether a new Commissioning window has been opened by an Administrator, using either the OpenCommissioningWindow command or the OpenBasicCommissioningWindow command. This attribute must revert to WindowNotOpen upon expiry of a commissioning window. An initial commissioning window is not opened using either the OpenCommissioningWindow command or the OpenBasicCommissioningWindow command, and therefore this attribute is set to WindowNotOpen on initial commissioning.

| Property | Value |
|---|---|
| Type | CommissioningWindowStatusEnum |
| Conformance | `M` |
| Access | R (read: view) |

Values (`CommissioningWindowStatusEnum`):

| Value | Name | Meaning |
|---:|---|---|
| 0 | `WindowNotOpen` | Commissioning window not open |
| 1 | `EnhancedWindowOpen` | An Enhanced Commissioning Method window is open |
| 2 | `BasicWindowOpen` | A Basic Commissioning Method window is open |

Example:

```json
{
  "0/60/0": 0
}
```

---

## Attribute `1` / `0x0001` — `AdminFabricIndex`

Path example:

```text
0/60/1
```

When the WindowStatus attribute is not set to WindowNotOpen, this attribute indicates the FabricIndex associated with the Fabric scoping of the Administrator that opened the window. This may be used to cross-reference in the Fabrics attribute of the Operational Credentials cluster. If, during an open commissioning window, the fabric for the Administrator that opened the window is removed, then this attribute is set to null. When the WindowStatus attribute is set to WindowNotOpen, this attribute is set to null.

| Property | Value |
|---|---|
| Type | fabric-idx |
| Conformance | `M` |
| Access | R (read: view) |
| Qualities | nullable |

Example:

```json
{
  "0/60/1": 1
}
```

---

## Attribute `2` / `0x0002` — `AdminVendorId`

Path example:

```text
0/60/2
```

When the WindowStatus attribute is not set to WindowNotOpen, this attribute indicates the Vendor ID associated with the Fabric scoping of the Administrator that opened the window. This field must match the VendorID field of the Fabrics attribute list entry associated with the Administrator having opened the window, at the time of window opening. If the fabric for the Administrator that opened the window is removed from the node while the commissioning window is still open, this attribute must NOT be updated. When the WindowStatus attribute is set to WindowNotOpen, this attribute is set to null.

| Property | Value |
|---|---|
| Type | vendor-id |
| Conformance | `M` |
| Access | R (read: view) |
| Qualities | nullable |

Example:

```json
{
  "0/60/2": 1
}
```

# Command: `OpenCommissioningWindow`

## Purpose

This command is used by a current Administrator to instruct a Node to go into commissioning mode. The Enhanced Commissioning Method specifies a window of time during which an already commissioned Node accepts PASE sessions. The current Administrator specifies a timeout value for the duration of the OpenCommissioningWindow command. When the OpenCommissioningWindow command expires or commissioning completes, the Node must remove the Passcode by deleting the PAKE passcode verifier as well as stop publishing the DNS-SD record corresponding to this command.

## Command Identity

| Field | Value |
|---|---|
| Command ID | `0` |
| Command hex | `0x00` |
| Command name | `OpenCommissioningWindow` |
| Direction | client → server |
| Conformance | `M` |
| Response | status |
| Access | (invoke: admin, timed) |

## Payload Fields

| ID | Field | Payload key | Type | Conformance | Constraint | Meaning |
|---:|---|---|---|---|---|---|
| 0 | `CommissioningTimeout` | `commissioningTimeout` | uint16 | `M` | desc | This field specifies the time in seconds during which commissioning session establishment is allowed by the Node. |
| 1 | `PAKEPasscodeVerifier` | `pakePasscodeVerifier` | octstr | `M` | allowed: 97 | — |
| 2 | `Discriminator` | `discriminator` | uint16 | `M` | 0 to 4095 | This field is used by the Node as the long discriminator for DNS-SD advertisement") for discovery by the new Administrator. |
| 3 | `Iterations` | `iterations` | uint32 | `M` | 1000 to 100000 | — |
| 4 | `Salt` | `salt` | octstr | `M` | length 16 to 32 | When the command is received by a ICD, it must enter into active mode. The ICD must remain in Active Mode as long as one of these conditions is met: - A commissioning window is open. - There is an armed fail-safe timer. |

# Command: `OpenBasicCommissioningWindow`

## Purpose

This command may be used by a current Administrator to instruct a Node to go into commissioning mode, if the node supports the Basic Commissioning Method. The Basic Commissioning Method specifies a window of time during which an already commissioned Node accepts PASE sessions. The current Administrator specifies a timeout value for the duration of the OpenBasicCommissioningWindow command. If a commissioning window is already currently open, this command must fail with a cluster specific status code of Busy.
